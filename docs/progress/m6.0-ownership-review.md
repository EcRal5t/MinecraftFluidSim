# M6.0 世界 ownership 设计评审（已关闭）

2026-08-22 关闭。结论：**选择方案 B"空气 + 独立 ownership registry"，拒绝方案 A"代理占位方块"**。本记录保存证据、冻结的共同状态机、提交顺序、崩溃恢复判定与格式边界；M6.1 按此实现。产品范围见 [`../roadmap/product-roadmap.md`](../roadmap/product-roadmap.md)，主题规格见 [`../roadmap/world-integration.md`](../roadmap/world-integration.md)。

## 原型与取证方式

- 方案 A：一次性注册 `realwater:fluid_proxy`（实心基线）与 `realwater:fluid_proxy_air`（无碰撞/不遮挡）两个占位方块，仅 `/give` 可得。机制矩阵由用户在专用测试世界实机取证（下表）。**决策后整类已删除**。
- 方案 B：`src/main/java/com/example/simulation/ownership/` 一次性事务原型——journal codec（v1：Dimension/Base/Target/Operation/Blocks）、committed registry codec（v1：RegionId/Dimension/Generation/Owned）、原子文件发布（journal/WARNING 拒绝覆盖；committed 回读校验后最后原子替换，是唯一提交点）、acquire/release/recover/reconcile 事务与 `/realwater ownproto` 命令。事务核心保留，M6.1 在其上正式化。
- 自动门：`runM6OwnershipPrototypeValidation` 覆盖 21 个场景（codec 严格性、正常 acquire/release、玩家占用跳过、代次推进、journal 发布前/后、逐块移除中、恢复中、committed 发布前/后、完成删除前故障注入、损坏/代次失配/维度失配/孤立 WARNING 锁死、reconcile 分类、临时文件、非原子文件系统 fail-closed）。其中两个决定性场景：**committed 发布前崩溃 → 世界全量回滚 preimage**；**committed 发布后崩溃 → 完成 ownership，绝不恢复 preimage**（杜绝复制水）。

| 机制 | 实心代理 | 类空气代理 | 对 ownership 表示的后果 |

## 拒绝方案 A 的理由

1. **静默侵蚀**：活塞、爆炸、水流、落沙、玩家破坏都会移除或移动代理，且原版不产生任何可拦截的通知事件。ownership 表示随时间不可验证地退化，维护它需要为每个机制叠加防御校验——这正是世界集成规格禁止的"长期依赖持续修补"。
2. **两个变体各损失一类核心体验**：实心变体挡光、挡通行，owned 区域内部不可用；类空气变体被水冲毁、坠落沙穿透、无法承载火把/铁轨等邻居方块。
3. **存档污染**：代理是非原版方块，Mod 移除后残留未知方块，`/clone` 可复制到未管理区域。
4. 方案 B 的对照优势：世界永远是干净原版方块；失败模式全部响亮（fail-closed 锁 + 可读报告）；崩溃恢复由 committed generation 唯一决定，不按时间戳/文件大小/槽位新旧猜测；存档成本趋近于零。

## 方案 B 已知限制（带入 M6.1）

1. **原版水可流入 owned air**（边界破口或开放边）。实测确认（26 个流入格被检出）。M6.1 对策：控制器闭合外壳是第一道防线；流入策略必须显式（对账分类 + 管理员处置），不得静默吸收或忽略。
2. 取证中发现并已修复：流入产生的 flowing 水状态（level>0）最初被 `inspect` 的严格状态相等比较归为"玩家方块冲突"；已改为整个水族（任意 level）计为"原版水回流"，与 restore 的占用判定一致。
3. registry 与世界方块是两套持久域，依赖加载时对账；这由下方状态机与判定表约束。

## 冻结：共同状态机（M6.1 实现依据）

```text
LEGACY_CONTROLLER ──prepare──> PREPARED ──HEAD 发布──> OWNED_COMMITTED ──release──> RELEASING ──> （无 ownership）
        └────────────────────────┴──────────┴──────────────┴──> LOCKED（任意未知/损坏/失配/超预算/不可自动解决的冲突）
```

- **LEGACY_CONTROLLER**：现行只读采样控制器（原版水保留在世界中）。
- **PREPARED**：目标 generation 的区域/ownership 状态已完整写入非活动槽并验证，WAL 与 WARNING 已落盘，但 HEAD 尚未指向新代。
- **OWNED_COMMITTED**：HEAD 已发布为最后提交点；marker + ownership registry 是权威，原版水 preimage 失去物理权威，**任何恢复路径不得再写回**。
- **RELEASING**：显式解除事务期间区域暂停、禁止容器转移与新 ownership 变更。
- **LOCKED**：未知版本、损坏、混合 generation、WAL 与 manifest 不一致、超预算、玩家冲突无法自动解决。保留数据、拒绝新事务、可读报告。

## 冻结：acquire 提交顺序

1. 区域暂停；所需 chunk 全部已加载；验证当前 HEAD = G。
2. 采集世界 preimage，候选仍只允许纯 `Blocks.WATER`。
3. 构造完整 G+1 区域/ownership 状态，写入非活动槽，force、回读并验证全部身份/校验和/账本不变量——**此时不得发布 HEAD**。
4. 写 ownership transition WAL 并 force；写 WARNING 并 force。
5. 执行世界修改，逐块验证；玩家实体方块冲突不覆盖、计入跳过。
6. **最后原子发布 HEAD = G+1**；终验；清理 WAL/WARNING。

## 冻结：崩溃恢复判定表

| 启动观测 | 判定 | 动作 |
|---|---|---|
| HEAD = journal.base | PRE-COMMIT | 回滚世界 preimage（玩家方块优先）；清理未提交代次 |
| HEAD = journal.target | POST-COMMIT | 完成 ownership 表示；**绝不恢复 preimage** |
| 其他 generation / 损坏 / UUID 失配 / WAL 与 manifest 不一致 | LOCKED | 保留数据、拒绝新事务、报告 |

禁止按时间戳、文件大小或槽位新旧猜测权威状态。

## 冻结：release 保守语义

release 是显式事务，不是崩溃恢复。M6.1 首版保守：区域暂停、无未完成 WAL、液体可无损映射回原版（或已排空）才允许；存在 partial/混合物/任意自由面时**拒绝并提示先用容器转移**，绝不近似生成原版水源。原型中 release 直接恢复 preimage 是因为原型不接求解器；M6.1 不得沿用该简化。

## 冻结：格式与迁移

- ownership sidecar 独立版本，不并入 `takeover-journal v1`、不改写 `region-state v1/v2`。M6.1 把原型布局（`realwater/ownership-proto/`）正式化为按区域 UUID 组织并与 region-state checkpoint generation 绑定；旧 reader 保留。
- 新配置门 `worldBridgeEnabled`（server.properties `FORMAT_VERSION` 升 3；v1/v2 读取时强制 false；非法值 fail-closed）。门关闭时拒绝新 ownership/容器入口，已有状态保留、只读、不删除。
- Mod 降级/移除遇未解决 ownership：WARNING 语义保证 fail-closed 提示，不静默删物质。
- **section 持久化不需要新格式**：region-state 已按 chunk section 分片存储、region 级原子代提交；"按 chunk 持久化 ownership 水"由现有布局 + ownership sidecar 满足，不引入 section 独立提交。
