## 先记住交付对象

目标是可玩、守恒、架构精简的完整 GPU 后端。64³ 完整步 20 Hz 与同场景十倍提速属于待证明目标；功能、硬件和可观察精度明确后，可以据完整成本调整支持范围。一次低效实现不足以证明不可实现。

**先让耗时达标，再做集中物理验证。** 性能开发期间保留发现失效所必需的库存、容量与有限数值检查，复用失败短重放。有95%把握的改动直接推进。禁止用缩小原场景、增加迭代或子步预算、跳过功能来宣布性能成功。

评估单位始终是推进相同仿真时长的连续完整步：准备、建表、求解、输运、热化学、提交及必要展示／世界交接都要计入。性能重放用于回答具体未知问题；迭代次数、单个 shader 时间与 CPU 一致性都不能单独决定方案去留。

## 调研支持什么

| 一手依据 | 对本工程的启示与适用范围 |
|---|---|
| [McAdams 等，2010，几何多重网格压力求解](https://math.ucdavis.edu/~jteran/papers/MST10.pdf) | 规则地址、免显式矩阵和轻量层级可用于不规则体素流域。其共享内存 CPU 结果支持结构选择；本工程切格、高密度比、液气储容和 GPU 成本仍须单独判断。 |
| [Shao 等，2022，UAAMG](https://computationalsciences.org/publications/shao-2022-multigrid.html) | 代数多重网格在黏性问题上有价值，连续布局和 SIMD 同样重要。应比较建图加求解的总成本，不能把“通用图一律低效”当作结论，也不能移用论文加速比。 |
| [Basilisk all-Mach 实现](https://basilisk.fr/src/all-mach.h)及[可压缩两相实现](https://basilisk.fr/src/compressible/two-phase.h) | 局部两相状态、状态方程和 Poisson–Helmholtz 压力推进已有实现依据。半隐式压力有助于处理声学刚性；本工程有限孔流、颗粒占容与精确库存的联合闭合仍需推导。 |
| [Arrufat 等，2021，质量与动量一致输运](https://arxiv.org/abs/1811.12327) | 高密度比下，质量与动量使用一致通量很重要。库存、物种和携带能量应共享实际转移记录；该论文不替本工程证明整数容量可行性。 |

这些依据支持首先研究**固定空间、统一面关系、少量全域求解、共同守恒交接**。局部气体可能增加未知数、改变均压速度和混合行为，尚不能保证更快。气腔聚合是否删除，取决于整条替代链能否承担原物理职责并降低成本。

## 每增加一段计算，先回答三个问题

**它处理了什么真实状态变化？** 固定碰撞和固定邻接持久保存；动态占据、物性、开度按变化更新。相同空间数据供压力、输运、气体和导热共享。改变模块身份而产生的重编号、来源图、重复 CSR 和库存中转，优先从设计中消除。

**它为什么必须串行？** 保留“状态→力与约束→实际通量→后继库存及功→热化学→提交”的因果顺序。区分设备内的数据依赖与主机等待；每层建图、每批迭代返回 CPU 不是物理要求。CPU 等待通常包含 GPU 执行，二者不能相加当成优化空间。

**它让完整步少做了多少工作？** 修改前写清将删除哪些扫描、归约、派发、复制或重建。性能记录同时报告完整步墙钟、GPU 时间、提交／派发次数、活动量、建表成本与峰值显存。若只减少迭代却增加层级、临时图和交接，先重新核算总账。

## 新执行步最先解决的三个问题

### 容量与输运共同闭合

每个单元的最终液体体积必须由同一批实际面转移量得到，并满足未来固体占容后的真实容量：

`V_new = V_old + Σ入流体积 − Σ出流体积 + 相变体积源项`，且 `0 ≤ V_new ≤ C_new`。

供体供给、液气储容、固体排水与精确量化都参加这份结果。满液环路上的同时流入流出是合法流动；只按接收格旧空位截断会把它阻塞。一次连续压力投影也不能自动保证离散整数流可行。若精确修正经常重新路由全域大流量，说明主要约束仍被推迟到了后处理，应重新设计闭合方式。

[Basilisk VOF 源码](https://basilisk.fr/src/vof.h)明确要求 CFL≤0.5；其切格分支采用忽略部分固体占容的近似，相关守恒口径也随之改变。直接移植无法满足本工程真实切格容量。VOF 的浮点守恒与本工程整数／dyadic 库存要求也应分别处理。

### 切格、液封与小体积

[AMReX 的切格说明](https://amrex-codes.github.io/amrex/docs_html/EB.html#small-cell-problem-and-redistribution)指出，小开放体积会使显式推进的时间限制恶化，并介绍守恒重分配方法。结构网格和半隐式压力仍需面对输运的小体积问题。

可研究局部控制体合并或守恒重分配，但必须沿真实通路，保持原场景的隔墙、液封、孔口阻力和库存容量。静态索引可以复用，动态面系数和粗层连接仍要反映占据变化。数值合并不能偷偷改变权威物质量或跨越已解析隔墙。

### 动量与能量沿实际通量结算

压力冲量、实际质量搬运、气体压缩功、重力势能、接触反力与耗散热必须形成一致的离散关系。局部结算承担这些职责后，才能删除全域机械连通体及其能量分配。

精确库存、物种、内能与舍入账继续保留；可近似的是数值求解和未解析运动。离散机械误差与浮点舍入分开观察。完全排空必须搬走精确尾数；禁止用清零、裁剪负数或补热隐藏不闭合。稳定库存池也必须容纳真实材料和物种增长。

## GPU 执行原则

[NVIDIA Vulkan 建议](https://developer.nvidia.com/blog/vulkan-dos-donts/)支持减少小提交、复用命令和缩减冗余屏障，同时指出过度批处理也可能增加延迟。因此追求少量有足够工作的批次；普通步争取一次提交，实际按墙钟判断。零工作组派发仍有命令成本；把全部最大迭代实做一遍、或融合成占用率低的巨型 shader，都可能更慢。

[Khronos 同步示例](https://docs.vulkan.org/guide/latest/synchronization_examples.html)明确展示了设备内读写依赖的屏障和独立写入的合并同步。按真实依赖安排屏障与间接派发；跨工作组全域同步使用合法设备机制。主机负责输入、扩容、故障处理和最终采用，普通数值阶段留在设备。

数据按用途分为权威双代库存、共享静态几何／物性、可复用派生缓存和临时工作区。普通步交换代次；冷导入、检查点和按需展示各有明确时点。大量临时容量与重复副本本身就是需要审视的结构成本。

## 何时继续，何时换轨

1. **先说明删减，再写代码。** 给出完整步的数据流、必要全域同步、主要存储量，以及原路径的具体删除范围。复用已可靠的整数分份、热状态、局部 IMEX 和事务实现。
2. **先回答成本风险。** 保持原64³切格和32³颗粒失败输入；短重放定位后尽快回到原连续场景。性能先行，同时防止以零流量、停滞或缺项取得虚假低耗时。
3. **出现结构性反例立即审视整步。** 修一个局部问题却需要另一套图、另一份库存或更深主机反馈，视为换轨信号。不得无止境增加预条件层次、试验分支和小参数。
4. **按完整模块交付。** 核心实现、调用迁移、正常流程、旧路径删除一起完成；过渡实现有明确退出点。当前压力图实验的暂停保持，恢复须有整步设计理由。
5. **结论限定证据范围。** 约35 ms的已有功能预算用于给全功能50 ms留余量，属于工程目标。不可实现的判定须说明硬件、功能、精度、规模和主导成本；方案尚未实现只能说明工作未完成。

**恢复工作时先问自己：这一轮是否减少了完整步必须做的事情，还是又在为现有中间表示增加维护代码？**
