# GPU 完整步：深入调研补充

2026-10-26。只读研究备忘录，恢复 GPU 实施时与[原则备忘录](gpu-execution-principles.md)一同阅读。本文记录论据、适用条件与决策约束；当前进度归[实施计划](../roadmap/solver-consolidation-plan.md)，运行结果归[验证指南](../maintenance/validation.md)。修改本文须有用户明确要求。本轮未构建、未运行 GPU、未增加物理验证。

## 结论与需要修正的判断

应继续重新设计完整计算步，并暂停扩展当前压力预条件器。方向是减少必须求解的自由度、重复库存组织和主机反馈；“全部改成逐格气体，再配一个多重网格”仍只是未经成本证明的方案。下一步优先考察**固定空间寻址、共享面通量、按需聚合气体压力自由度**，避免在删除旧图的同时增加产品不需要的气体动力学。

本轮源码核对发现：现有容量器已经是供体→接收单元→唯一所属组→汇点的单商品网络；当前气体契约则主动忽略腔内声波、空间动量和混合层。这两点分别提供了整数可行性的结构优势和气体降维的机会，重设计应利用它们。

## 1. 库存地址与压力未知量分别选择

[气体契约](gas-state.md)采用腔内均匀压力和温度。把每格气体都赋予独立动量、温度和声学演化，会增加空间通量、状态函数和热压力耦合，也改变已有玩法响应。稳定空间地址值得保留；求解自由度应按实际需要压缩。

Goldade 等的研究用约束气泡省去零密度气泡内部输运与投影；另一种有限密度、不可压仿射模型在三维区域内部只保留 11 个速度自由度。这证明图形仿真可以主动降维。其模型并未交付本项目的有限气体组分、可压 EOS 和热化学，性能也不能直接移植。[论文与作者实现](https://cs.uwaterloo.ca/~c2batty/papers/Goldade2020/)

优先比较两个有限范围的设计，最终保留一个生产实现：

| 方案 | 可省去的工作 | 必须计入的代价 |
|---|---|---|
| 空间库存＋气腔压力／温度聚合 | 腔内声学与动量；保持现有均压模型；液体规则网格与少量气体节点耦合 | 成员汇总、拓扑拆分合并、组分与内能分配；聚合本身仍需全域通信 |
| 空间库存＋局部半隐式气体状态 | 每步气腔重编号及来源重映射；局部面计算更统一 | 更多压力未知量、气体输运与温度状态；均压速度改变；刚性热压力反馈 |

原切格输入有大量受限孔口，日志初始气体节点达 65,576，不能把它假设成“一个大气腔”。聚合收益应由原输入中实际节点与界面数量决定。动态湿干连通关系不变时复用成员；删除一条关键通路可能造成大范围气腔分裂，不能承诺只重算附近几个格子。若选择局部状态，需要明确替代均压模型产生的可观察误差。

共同压力允许“规则液体算子＋气腔／孔口稀疏耦合”。腔体求和与广播可直接执行矩阵乘积；避免显式消元造成液体单元间稠密连接。是否聚合、是否分层，都按**建表＋求解＋库存交接**总成本决定。

## 2. 压力与容量联合闭合的真实难点

一个可研究的连续形式是：以七路偏好为目标，在守恒、接收单元上下限、有限组容量和实际开放通路下求受约束通量。液体压力是体积约束的对偶量，孔口流阻与气体储容进入相同物理关系。固定约束集合时，局部面响应可能产生适合空间多重网格的算子；接触集合改变、供体耗尽和容量约束激活仍会引入非线性或外层迭代。将方程写成一个系统并不保证执行轮数减少。

源码 `liquid-capacity.comp` 的 `endpoints/lower/upper/groupOf` 表明当前容量限制具有普通网络流结构。在整数上下限和整数节点供需下，连续可行流存在则整数可行流存在。进一步把每条边限制在该连续流的向下／向上整数之间，仍有整数可行解：连续流满足新上下限，再用网络流整数性即可得到。这是本轮根据标准定理作出的推论。[下界转换](https://www.cs.odu.edu/~toida/courses/CS600.03fa/notes/lowerbound-flow/index.html)、[MIT 网络流讲义](https://courses.csail.mit.edu/6.854/20/Notes/n06-flow.html)

这个机会有三个严格前提：

1. 连续结果已满足同一网络的全部约束。普通近似压力解尚不具备这个保证。
2. 以容量量子计的残差足够小。现有容量基准量子为 `2^-40`；在单位量附近，FP32 的一个间距约为 `2^-23`，相当于 131,072 个量子。求解浮点误差与一量子的整数舍入要分别处理。
3. 重设计继续保持网络结构。若增加任意重叠组约束或多物种独立容量竞争，不能直接沿用上述整数性结论。

即使每边只差一个量子，协调路径仍可能跨越整片区域，整数性不保证局部固定轮数。满液环流也说明：每格旧空余量为零，整圈同时转移却可行。按接收格旧空余量截断会禁止正常流动。

因此下一次性能样机要直接统计连续残差、整数修正搬运量和传播范围。若整数修正经常承担大量重新路由，或联合求解又增加多层全图迭代，应更换离散与耦合策略；继续给末端修正加预算没有交付价值。

## 3. 切格：守恒、容量与静止状态需要同时考虑

小切格可采用邻域合并或守恒重分配来减轻显式时间步限制；邻域必须遵循真实开放通路。固定几何的邻域与权重可以缓存，移动固体和变化中的流体可达关系仍需更新。

Berger 与 Giuliani 的加权状态重分配研究给出特定条件下的单调性和稳定性，适用条件包括网格配置与 CFL，不能概括成任意三维多相场景均成立。[2024 版本](https://arxiv.org/abs/2308.16332)

同作者 2026 年 10 月的研究进一步指出：对状态本身重分配会改变原格式的稳态；改为重分配更新量可保持原格式稳态，却失去加权状态重分配的单调性保证。文中主要展示二维例子。这是新的反例依据，尚不足以直接选择其算法作为本项目方案。[Delta Redistribution，式 1 与表 1–2](https://arxiv.org/html/2610.06459v1)

工程取舍：优先保留静水平衡、非负库存和真实切格容量。只有某种稳定化确实减少完整步时间，才引入其邻域与额外派发；精确总账不能代替局部容量或稳态要求。性能合格后再集中检查可观察的静水漂移和界面扩散。

## 4. 热压力反馈不能从成本表中消失

Saade 等在 all-Mach 两相方法中加入导热后，采用压力与温度双向耦合的多重网格求解，讨论了相较显式处理的稳定性和精度改善。其问题覆盖空化等强瞬态，本项目没有自动继承其全部求解要求；但它揭示了“局部气体＋现有热学末端一步”并非无条件成立。[论文，式 8–10](https://arxiv.org/pdf/2206.11294)

对本产品可优先保留分裂推进和局部 IMEX，用单步热交换相对热容、压缩功相对内能的大小判断耦合强度。强耦合只在实际参与的设备、气体和相变载体中处理；避免每个格子都执行一套通用非线性系统。相变引起的体积变化必须参加同一步容量闭合，导热与反应消耗的内能必须来自同一候选。各物理职责的调用顺序、重复求解次数和总耗时都计入完整步。

## 5. 后续执行应提交什么

先用一页运算表明确：权威库存、共享几何、压力自由度、实际面通量、整数交接、热化学、提交。每项标出重建条件、全域通信与 CPU 反馈。固定碰撞邻接复用，液面／湿干几何同代只生成一次，材料和能量共享已接受转移；由表示转换产生的全域 CSR、来源重组和重复库存归并集中删除。真实压力传播、拓扑分裂和容量协调保留所需设备同步。

恢复实施后的第一份性能结果必须包含原 64³ 切格连续液气导热链，记录建表、所有求解、精确输运和提交。短重放只用于淘汰方案。现有功能段约 35 ms 是为完整 50 ms 留余量的工程目标；反应、相变、生产交接和展示尚未计入的成本须明确列出。无工作阶段采用间接零工作组派发，但它只减少无效 GPU 工作，不能补救过长的计算链。

当前证据说明结构性重设计有必要，尚不能断言目标不可能，也不能保证目标可达。不可实现的判定应落实到 RTX 5070 Ti、原场景、实际功能和允许误差下的必要成本，并说明降低哪项要求能改变结论。全功能未完成或某一预条件器失败，都不足以作出该判定。
