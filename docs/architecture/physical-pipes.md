# 单方块薄壁管道

MMM 管道以独立有限管腔保存物质；普通区域继续负责管外三维流体。相邻管段和区域端口交换真实库存，管壁接入世界共享环境热场。Create 管道保留 Create 的运输规则，双方交接由适配层负责。

## 管件与布线

| 方块 | 用途 |
|---|---|
| `metal_pipe` | 普通金属管，参与管内外换热 |
| `insulated_pipe` | 绝热管，采用已有绝热材料热物性 |
| `glass_pipe` | 透明观察管，显示接受后的液层及床体 |
| `insulated_glass_pipe` | 透明绝热观察管，保留内部视野 |
| `pipe_valve` | 轴向管阀，关闭、半开、全开，支持红石 |
| `pipe_screen` | 轴向管筛，配置粒径阈值及开放率 |

放置沿点击面轴线建立直管，另外四面封闭，并排管线保持独立。潜行空手点击单面，在手动开放、封闭、自动连接之间切换，可布置弯头、三通及多支路。四种管材的对向开放端可互连。探针可读取管腔容量、实际液量、压力和床库存。

管件只占据部分方块：主体外宽 0.625 m，内径 0.5 m，壁厚 0.0625 m。模型和碰撞统一对齐 1/16 m；连接臂伸到相应方块边界。直管开放截面为 0.25 m²，容量为 0.25 m³（250 L）。封端、弯头、三通和阀板使用各自真实内腔体积。

每面保存自动封端、自动连接、手动开放、收回支管四种状态。自动封端保留带端盖的连接臂，收回支管使用主体侧壁。外包络、内腔、管壁由 `PipeGeometry` 共用生成；四材质模型与 729 种端口几何组合有对应检查。

## 物质归属与求解

每个管段保存气体组分、液体物料和组分、床库存及各自内能。液体体积在管网中使用 m³，区域库存使用格体积单位，交接显式按 h³ 换算。质量、物种和固体体积保留原整数单位；能量舍入单独记账。

`PipeNetworkSolver` 计算压力和高差驱动的有限容积输运。通流阻力使用黏度、长度、开放面积及床层渗透率；以压力顺应性和可用库存限制同一代次的多出口流量。所有出口从原代库存统一分配，避免分支次序产生物料偏差。气体压缩功、重力势能、液体弹性能及耗散热一起闭合。

管腔采用段平均状态，管内速度剖面、湍流和弯头局部涡流不在此离散中解析。当前管径以等效 Poiseuille 阻力建模。气液相变复用世界材料的饱和关系、物种定义和热参考能；冷凝可以从零初始液体开始，气化消耗实际液体及相变所需能量。

床层通过实际液体通量计算冲刷剪切，按材料起动阈值搬运颗粒；多出口共享源库存，筛网按粒径截留。固体质量、物种、体积和内能随床载迁移，床层占容与渗透率影响后续通流。当前颗粒以步末床库存表示。

普通区域用静止实体包络表达整段管道所占的壁体和独立管腔，外部流体保留包络之外的真实空间。管壁不再按粗微格投成整块实墙。固定碰撞、实体占容和库存排布先在私有候选中检查；超过几何或实体预算时保留旧物理状态。

## 区域端口与生命周期

`PipeEndpointResolver` 按真实管口的 8×8 像素面映射相邻区域格，并剔除被实墙遮挡的微面。流体端口外侧可通向其所属区域内部。普通区域保持各自身份和求解范围，管道连接不会扩大或合并整个区域。

区域接口作为有限库存临时段参与同一次候选。气体、液体和物种在同一轮计算后回写各自所有者，区域面动量随质量更新，移出动能进入相连管段的热库存。所有区域设备状态先独立准备并成功导入，再统一交换引用；准备失败时各源保留原代次。

新建管腔从所在空间划分实际物质。已跟踪的环境空气保留原气体组成和内能；机械区域按真实管腔与源格相交体积，从该格的有限容积混合库存划分物质。首次进入跟踪范围的空气采用世界环境初始条件。管腔与管外库存分别拥有唯一来源。

拆除前须排空液体和床库存，剩余气体原样返回外部有限空气或相邻机械所有者。库存检查覆盖普通销毁和爆炸掉落之前的入口。调整管口或阀板时检查新容量，并结算有限气体的压缩功。

区块卸载断开涉及该区块的边，冻结相应段的物质、相变和热交换；已加载的独立段继续推进。恢复后按接受的方块身份和端口重建连接。

## 共用环境热场

管壁使用真实实体体积、材料密度及有限热容。四种材质由既有方块热标签和世界材料定义选择。内侧热阻使用半壁厚和管内载体热物性；外侧连接已有有限空气、普通区域流体或相邻固体节点。

管内、管壁和管外空气分别存储能量，墙体只保留一个世界热节点。管内气体受热引起的液体弹性能变化同时结算，管腔与墙体的热交换增量逐次互反。机械格上的外壁接触按真实 1/16 m 壳面聚合，CPU 和 GPU 热端口共享面积比例。

运行时批量读取一代墙节点，准备管侧与环境侧候选后共同采用。缺失已加载墙节点时等待完整热拓扑，保留原库存。管网默认每 4 个服务器 tick 推进一步（0.2 s），使用有界有限容积候选控制分支流量和热交换。

## 存档与显示

每维管网、接受的方块属性、能量账、世界环境和普通区域写入同一世界 HEAD 代次。版本 3 世界快照包含独立管网，版本 2 世界读取为空管网。未提交候选、损坏数据和过期区域代次均有回归检查。

服务端发布管腔库存及接受的内腔形状，客户端按完整代次组装分片。液层按物料密度排序，床体按实际体积显示；使用现有流体渲染批次处理透明排序和深度。加入、重生、跨维和断线均沿现有协议会话清理及重发。

## 验证入口

- `:solver:runPipeLiquidTransportValidation`：气液分支、压差与高差、关闭阀、相变、冻结段、质量和总能量。
- `:solver:runPipeWallHeatValidation`：有限管壁、四材质热阻、长时间步有界性及混合气液弹性能。
- `:fabric:runHostValidation -PhostValidation=shape,pipe-network,lifecycle,environment,protocol`：真实几何、布线、区域交接、失败回滚、环境空气归属、存档和客户端分片。
- `:fabric:runArchitectureValidation`：模块依赖及文件规模。

普通区域的 GPU 流动、沉积、筛网和共享热场保留各自回归；管腔求解的验证直接覆盖独立管网模型。
