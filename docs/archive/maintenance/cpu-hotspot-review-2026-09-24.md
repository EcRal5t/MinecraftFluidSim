## 修正的测量问题

旧程序位于未跟踪的 `build/full-profile/CompositeProfileBenchmark.java`。它的组合结果及派生收益判断已经撤回，原文保留供审计；该程序入口已停用。正式入口为 [CompositeStepBenchmark](../../../fabric/src/test/java/cc/ecisr/mmm/simulation/CompositeStepBenchmark.java)，参数见 [验证指南](../../maintenance/validation.md#performance)。

| 原问题 | 补正 |
|---|---|
| 四分之一子格细砂被赋予 650 kg，密度高出八倍 | 从 SVQ 和注册表密度推导质量，每组为 81.25 kg；检查注入结果 |
| 刚体请求高于液面，9 步原轨迹没有接触或沉积 | 连续推进至真实沉积，再按液体粒子位置选择床面附近请求；输出接触数、冲量、沉积及唤醒次数 |
| 热化学场景仍是纯水，50 步没有化学变化或固体析出 | 持续注入酸碱和盐离子，采样阶段必须观察到化学变化与析出 |

| 分配统计包含额外快照、恢复、导出及格式化，耗时却提前结束 | 时间和分配统计使用相同工作范围；展示场景分别记录捕获、恢复、快照、网格生成 |

新入口没有接入 Minecraft 到期调度、网络编码、存盘和 GPU 绘制。展示场景测 CPU 网格生成。`mixed` 显式安排区域工作，不据此声称生产活动分类已经验证。

## 颗粒优化的拆分对照

沿用本机 OpenJDK 26.0.2，目标 Java 25。同一时刻只运行一个仿真测量进程，交错启动独立 JVM。普通计时不启用 JFR，不生成状态摘要。所有方案使用相同的化学交接和参考能优化，只替换 `207b852` 涉及的三个颗粒类。

- `baseline`：`207b852^` 的三个颗粒类。
- `current`：`207b852` 的完整改动，原始列读取与邻接索引预计算。
- `columns`：仅原始列读取。
- `neighbors`：仅邻接索引预计算，即此次保留的实现。

大场景有 20,736 个初始液体粒子、1,536 个活动细砂 parcel。每次重放同一初态，执行完整后端计算和提交，初态捕获在计时外。这样活动颗粒不会在预热中全部沉积；结果描述该固定负载，不代表长时间演化的平均成本。每次预热 40 步、采样 60 步。

| 方案 | 独立 JVM 次数 | 各次均值 ms | 合并均值 ms | P95 ms | MiB/步 |
|---|---:|---|---:|---:|---:|
| baseline | 3 | 201.281、194.149、195.294 | 196.908 | 225.954 | 49.852 |
| current | 3 | 188.645、188.338、180.802 | 185.929 | 210.787 | 49.621 |
| columns | 2 | 195.323、201.079 | 198.201 | 222.606 | 49.524 |
| neighbors | 2 | 176.507、184.333 | 180.420 | 203.359 | 49.927 |

原始列读取单独使用时没有收益，减少的分配不足 1%。它增加了 12 个公开标量访问方法，并将多个求解循环改为重复读取单列，因此撤回这部分修改。`GranularPressureCoupling` 和 `GranularParcelStore` 恢复到该优化之前的实现。

邻接索引预计算保留在 `GranularImplicitDrag` 内，新增一个候选工作数组，按每个耦合面 27 个整数保存面索引，每次建立耦合关系时更新。它避免 PCG 内层重复计算邻居索引，当前大场景平均降低约 8.4%，代价为约 0.15% 的每步分配增长。相比原始颗粒实现，只剩这一处局部优化，未新增跨模块接口。

256 个活动 parcel 的固定初态重放每次预热 80 步、采样 160 步。baseline 四次均值为 21.541、24.534、25.217、23.487 ms，neighbors 两次为 21.962、22.521 ms；合并均值 23.695 → 22.241 ms。小场景波动与收益幅度接近，只作为辅助结果。

演化到全沉积的小场景也执行了三方案各三次测量，但采样段已没有活动 parcel，不能证明活动颗粒求解优化有效。更早报告中的空颗粒 4.8% 差异同样不支持这项结论。

## 实际过程覆盖

最终组合程序的单次入口检查结果如下。这些是过程覆盖和测量范围检查，不能单独用于优化收益比较。

| 场景 | 预热 + 采样 | 观察 |
|---|---|---|
| granular | 80 + 160 | 全轨迹沉积 256 个 parcel、累计接触粒子计数 46,689；采样段接触 32,134，沉积发生在预热段 |
| thermochem | 20 + 80 | 全轨迹变化粒子计数 172、析出操作 590；采样段分别为 152、493 |
| mixed | 20 + 80 | 采样段 40 次运动入口、80 次热轴入口、120 次区域跳过；刚体接触计数 8,991 |
| presentation | 20 + 80 | 捕获 2.532 ms、恢复 10.709 ms、四种快照 3.042 ms、液面网格 5.969 ms；各阶段另有分配列 |

颗粒场景的唤醒次数为零，尚未覆盖床沙再次起动。当前结果能证明沉积后请求确实作用于液体，不能证明侵蚀或再悬浮。热化学入口包含外部注液与待处理相变体积结算，运行次数及操作耗时不等同于纯求解器成本。过长注入达到容量限制会显式失败。

所有过程运行都检查气体及精确内能收支。CSV 过程观测在颗粒拆分对照中一致。另在独立运行中复用既有完整状态编码器，对 baseline 与 neighbors 的 240 步沉积扰动输出及大场景两次固定初态输出比较 SHA-256，共 242 对全部相同。摘要覆盖完整 handoff 状态，排除派生缓存，注册表以 fingerprint 表示；这项运行的耗时没有纳入性能表。
