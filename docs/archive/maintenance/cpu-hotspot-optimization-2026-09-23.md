# CPU 仿真热点优化 — 2026-09-23

## 范围与方法

基准提交 `4d53c61`。本轮按上一轮 `build/full-profile/REPORT.md` 的优先级处理化学捕获/恢复、组成池扩容和热参考能重复计算。生产改动分别提交为 `320d340`（化学交接）、`9804857`（共享参考能贡献）；`c640c3e` 将既有拆并长跑改走生产后端；`f8c36df` 根据新增 JFR 将缓存索引改为定义对象身份散列。

同机 OpenJDK 26.0.2，目标字节码 Java 25。四个原始场景均保持全能力配置、0.05 s logical step、气体及精确内能审计；测量覆盖捕获、后端恢复/计算与提交。优化前后各执行两次独立 JVM 测量，每次预热 100 步、采样 300 步。同一时刻只运行一个被测仿真进程。缓存计数、完整状态摘要和 JFR 分别运行，普通耗时表不混入这些诊断结果。

化学快照直接对不可变记录去重及规范排序，线性检查顺序；稳定 ID 表首次导出时生成。逐 marker 质量关系、species/余量总账、材料兼容性、区域数量上限都保留。恢复域独立拥有 packed 数组、marker handle、指示剂与反应队列。精确质量缓存绑定完整注册表对象身份，不改变有理数运算。

组成池按恢复时已知的 marker 数一次预留，减少固定 16 槽列逐级扩容的复制。候选仍建立私有计算状态；本轮没有复用跨候选可变工作数组。存档需要稳定 ID 表时仍支付转换成本，普通 CPU 交接可以直接使用完整的注册表绑定记录。

## 参考能缓存实测

旧缓存为 `LiquidEnergyColumn` 的 1,024 项 LRU，键含材料、质量 raw bits、完整化学记录及化学注册表。计数使用原始源码的独立编译覆盖层，未把计数器留在生产代码。

| 场景 | 旧缓存命中 | 旧缓存未命中 | 命中率 | 绕过液体列的 baseEnergy 调用 | 同一步内重复 baseEnergy 输入 | 同一步跨两路径的不同输入 |
|---|---:|---:|---:|---:|---:|---:|
| 控制器 | 1,213,023 | 35,482 | 97.16% | 777,291 | 749,956 | 35,480 |
| 大型溃坝 | 1,388,291 | 9,062,360 | 13.28% | 7,382,263 | 12,661,906 | 3,676,753 |

统计为预热后的 300 步合计。重复输入按材料、质量 raw bits 和稳定 species 数量识别；residual 不进入状态函数参考能公式。每步清空重复诊断集合，因此跨步骤重复尚未计入。大型场景实际执行 baseEnergy 共 16,444,623 次，其中 77.00% 的输入在当步已出现过。

新缓存位于共享状态函数，保存原有精确乘除后得到的单个 host/species 数量贡献。容量为 16,384 项，直接映射，命中不构造键对象；槽位冲突重新计算。质量项和逐物种累加顺序保持原样，使用原子引用发布完整缓存项。

最终新缓存控制器命中 1,621,292 / 1,682,847 次（96.34%）；大型场景命中 8,852,234 / 17,832,914 次（49.64%）。字符串索引阶段的命中率分别为 96.34% 和 49.61%，更换索引没有实质改变命中率。这里的分母是所有路径的物种贡献查询，旧表的分母是液体列完整参考能查询，两表采用不同的查询粒度。大型场景仍存在槽位冲突和新候选中的首次查询，后续可结合实际复用距离继续评估缓存结构及生命周期。

## 完整状态与回归

`StateDigestBenchmark.java` 对四个原始场景的初态及随后 400 步逐步生成完整状态 SHA-256。覆盖所有不可变 handoff 字段，包括粒子 raw bits、材料、化学规范表、气体拓扑/库存、各载体内能与审计、待同步相变体积、压力场及调度状态。注册表按规范 fingerprint 编码，新增派生缓存排除在摘要之外。四组优化前后共 1,604 对状态摘要全部相同。最终身份索引版另生成 `*-identity-digests.csv`，与同一基准的全部 1,604 对摘要再次一致。

普通计时的四个场景、基准与最终版本共 16 轮中，每轮全部 400 步的粒子数、子步数、PCG 次数和打印残差也一致。摘要是独立运行，计时窗口没有包含摘要和稳定 ID 表导出成本。

最终编译与 `verifyArchitecture` 通过；`chemistry,thermal,thermal-extremes,lifecycle,region-state,reseeding,granular,production-replay,production-live-budget` 九组完整测试通过，总计 75.764 s。强化的既有测试覆盖注册表切换及并发精确质量查询、冷恢复与快照隔离、反序规范表拒绝，以及超过缓存容量的跨材料/物种数量、相反累加顺序和并发参考能查询。

两项原始 5,000 步拆并长跑均已正式走生产后端。溃坝完成后 marker=1568，merge/split=10405/10245，原有精确体积及分布断言通过。身份索引变更后重新编译，并通过 `thermal,thermal-extremes,production-live-budget`，用时 5.985 s；最终正式大型场景前 20 步最大 177.966 ms，没有连续三步超过 200 ms。

## 长跑与剩余热点

双次注液的单气腔断言仍失败：一个 0.007127152843087973 m³ 的真空气腔，另一个含气腔 33.99287284715691 m³；总标准气体库存 64 m³，source=64 m³、sink=0，审计闭合。与上一轮原始日志一致。该几何/测试期望问题保持原样，未通过修改断言隐藏。

字符串索引阶段的 1,000 步长跑已完成，预热后 900 步平均 83.916 ms、P95 95.409 ms、P99 101.797 ms，分配 65.626 MiB/步，GC 暂停 501.304 ms。后期不同记录数量仍约 13,600–14,200；采样发现索引中的 `StringLatin1.hashCode` 自身占 7.46%，随后改用已经参与键匹配的对象身份散列。

最终大型 JFR 共 6,432 个主线程计算样本：网格重建/P2G 28.45%、候选恢复 28.37%、参考能 22.79%、捕获约 9.4%、气腔拓扑 10.74%、压力求解 2.61%。这些调用树存在嵌套，不能相加为互斥阶段。参考能缓存自身仍占 7.14%，表明查询与未命中成本仍需关注，不能只凭字符串散列方法退出榜单判断成本消失。精确有理数构造/乘除约占分配采样 33.4%；候选恢复仍需建立组成池和其他工作数组。

控制器最终 JFR 有 235 个样本：气液相变 32.34%，其中几何刷新约 17.45%；网格重建/P2G 25.53%、候选恢复 19.15%。小场景的瓶颈仍集中在相变与几何，样本数量只适合判断主要路径。

后续优先按以下独立增量推进：

1. 拆分候选恢复中的 LTE 重建、`ThermalCellOperations` 临时整记录映射与固定工作数组成本；继续测参考能缓存的复用距离、槽位冲突和跨候选首次查询，维持失败候选与活动状态的隔离。
2. 量化 P2G、守恒压力体积散射和 PLIC 重建的重复遍历，再设计同代派生数据复用。
3. 控制器单独处理相变后的几何刷新，同时复核双次注液的真空气腔，保持气体 lineage、容量和 pending work 的原有校验。

这些是本轮复测留下的定位结果，尚未修改对应物理算法。
