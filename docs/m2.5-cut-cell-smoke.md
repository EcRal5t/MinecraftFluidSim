# M2.5 cut-cell 实机签收

此门只验证自动测试无法覆盖的真实 `BlockState -> VoxelShape`、服务器定时 refresh 和客户端视觉关系。它不使用 takeover，不修改存档格式，也不要求 GPU probe。

## 准备

1. 只启用本次构建的主 Mod jar，进入一个可丢弃或已有备份的测试世界。
2. 面向空旷地面执行 `/realwater demo`，随后 `/realwater pause` 与 `/realwater status`。
3. 从 status 记下 `origin X, Y, Z`、water cell-volume、marker 数和 `collision partial/full`。下面用 `OX/OY/OZ` 表示该 origin；命令中要替换成实际整数。

demo 左侧约 40% 宽度初始有水。选择域内一个水下方块位置，例如 `OX+2, OY+1, OZ+2`；若该位置不在蓝色水体内，沿 X 在 origin 附近调整，但不要放到黄色域边界外。

## Stair 开放空间与 exact 挤水

依次执行并保留每次完整命令输出：

```text
/setblock <X> <Y> <Z> minecraft:stone_stairs[facing=east,half=bottom,shape=straight]
/realwater refresh
/realwater status
```

预期：

- straight stair 的 0.5 方块边界恰好与 solver-cell 对齐，因此 partial 数可以不变；full 数应增加但不能按整个方块增加 8 格（常规 straight bottom stair 是 6 个 full solver cell）。
- refresh 不报 NaN 或异常；`escaped` 应为 `0.000`，water cell-volume 与放置前在显示精度内相同。
- 暂停画面中水可以占据 stair 的开放部分；允许当前 density mesh 与台阶表面有小于一个 solver cell 的视觉交叠，但不能把 stair 所在整个方块挖成空洞。

然后：

```text
/realwater run
```

观察约 10 秒后执行：

```text
/realwater pause
/realwater status
```

预期：水沿 stair 开放部分和两侧流动，不穿过实体台阶体积，不吸墙、不在墙角被锁死；status 的 PCG residual、`maxP` 和 step wall time 有限，water cell-volume 不变。

## 真正 fractional 的薄 barrier 与移除恢复

暂停时把同一位置换成 pane：

```text
/setblock <X> <Y> <Z> minecraft:glass_pane
/realwater refresh
/realwater status
```

预期 partial 相对 stair 明显增加（单独一个 pane 通常贡献 8 个 partial solver cell），pane 不从碰撞中消失，water 不穿过 pane 本体。随后移除：

```text
/setblock <X> <Y> <Z> minecraft:air
/realwater refresh
/realwater status
/realwater remove
```

预期 partial 数回落；移除障碍不会制造水，water cell-volume 仍与基线一致；`/realwater remove` 正常清除瞬态域且没有 takeover journal/WARNING。

## 签收材料

请提供上述 `/realwater status` 与 `/realwater refresh` 的 transcript，外加一句视觉结论：stairs 开放空间是否有水、pane 是否阻水、是否看到明显穿透或整格空洞。只有出现视觉异常时才需要截图。
