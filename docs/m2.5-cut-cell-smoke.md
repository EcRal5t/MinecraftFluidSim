# M2.5 实机签收

固定坐标 cut-cell、exact 挤水和小水滴观感已于 2026-08-19 通过。本门保留那些记录，并追加自动测试无法覆盖的客户端长期液面观感。它不使用 takeover，不修改存档格式，也不要求 GPU probe。

## 准备

1. 只启用本次构建的主 Mod jar，进入一个可丢弃或已有备份的测试世界。
2. 面向空旷地面执行 `/realwater demo`，随后 `/realwater pause` 与 `/realwater status`。
3. 从 status 记下 `origin X, Y, Z`、water cell-volume、marker 数和 `collision partial/full`。下面用 `OX/OY/OZ` 表示该 origin；命令中要替换成实际整数。

demo 左侧约 40% 宽度初始有水。本门固定使用 `X=OX+2, Y=OY+1, Z=OZ+2`；不要沿 X 调整。自动门已经对这个相对位置复现 2,592 格初始水、straight stair 挤出 6 格并在半径 8 内完整恢复，固定坐标可消除“障碍是否放在初始水体或恢复半径边缘”的歧义。

## Stair 开放空间与 exact 挤水

依次执行并保留每次完整命令输出：

```text
/setblock <X> <Y> <Z> minecraft:stone_stairs[facing=east,half=bottom,shape=straight]
/realwater status
/realwater refresh
/realwater status
```

预期：

- straight stair 的 0.5 方块边界恰好与 solver-cell 对齐，因此 partial 数可以不变；full 数应增加但不能按整个方块增加 8 格（常规 straight bottom stair 是 6 个 full solver cell）。
- setblock 后服务器定时 refresh 可能先处理变化，因此第一次 status 应保留 `last Δ6, escaped 0.000`；随后手动 refresh 即使报告变化 0，也不会覆盖 status 中最近一次非零碰撞诊断。
- refresh 不报 NaN 或异常；water 必须仍为 `2592.00 cells`、marker 必须仍为 `20736`。任一精确值下降都不签收，不能只看后来一次 `escaped 0.000`。
- 暂停画面中水可以占据 stair 的开放部分；允许当前 density mesh 与台阶表面有小于一个 solver cell 的视觉交叠，但不能把 stair 所在整个方块挖成空洞。

然后：

```text
/realwater run
```

观察约 10 秒后执行：

```text
/realwater pause
/realwater status
```

预期：水沿 stair 开放部分和两侧流动，不穿过实体台阶体积，不吸墙、不在墙角被锁死；status 的 PCG residual、`maxP` 和 step wall time 有限，water cell-volume 不变。

## 真正 fractional 的薄 barrier 与移除恢复

暂停时把同一位置换成 pane：

```text
/setblock <X> <Y> <Z> minecraft:glass_pane
/realwater refresh
/realwater status
```

预期 partial 相对 stair 明显增加（单独一个 pane 通常贡献 8 个 partial solver cell），pane 不从碰撞中消失，water 不穿过 pane 本体。随后移除：

```text
/setblock <X> <Y> <Z> minecraft:air
/realwater refresh
/realwater status
/realwater remove
```

预期 partial 数回落；移除障碍不会制造水，water cell-volume 仍与基线一致；`/realwater remove` 正常清除瞬态域且没有 takeover journal/WARNING。

## 签收材料

请提供上述 `/realwater status` 与 `/realwater refresh` 的 transcript，外加一句视觉结论：stairs 开放空间是否有水、pane 是否阻水、是否看到明显穿透或整格空洞。只有出现视觉异常时才需要截图。

## 长期液面趋稳复核

新增体积分布漂移约束部署后，新建一个 demo，不放障碍：

```text
/realwater demo
/realwater run
```

约 30 秒和约 2 分钟各执行一次 `/realwater status`，第二次之后观察液面片刻，再执行：

```text
/realwater pause
/realwater status
/realwater remove
```

这个 demo 是 dam-break，不要求起始平面原地静止，也不以固定 wall-time 推断固定 step 数；`REDUCED` 只表示调度因 CFL/成本降频。签收要求：

- 物理真值始终为 `2592.00 cells`，`skipped budget/geometry` 与 ledger error 均为零；
- 早期碰撞/飞溅阶段允许 marker 数、`in ... cells`、visible 和 dense 明显变化；到后两个 status 之间不应继续出现单向的大幅占据格/可见格减少；
- 液面应逐渐趋稳，不应在已经平缓后仍肉眼可见地持续一层层下降；局部波动、细小飞溅和不到一个 solver cell 的 mesh 抖动不算失败；
- 压力、残差和 wall time 必须有限。动态阶段进入 `REDUCED` 可以接受，进入 hard pause、出现 NaN、穿墙或 exact 水量变化则失败。

请提供三次完整 status 和一句视觉结论。若仍看到持续下降，再补一张相同视角截图或短录像即可，不需要重复 stair/pane 门。
