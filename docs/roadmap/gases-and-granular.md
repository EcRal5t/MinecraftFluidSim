# 气体、颗粒与沉积规格

本文保存 M5 气体网络和 M8 低成本颗粒模型的未来设计边界。它们共享材料库存，但不应被塞进当前液体核心。

## M5 气体网络

Minecraft 规模下采用“守恒区域网络 + 必要时局部细网格”，不逐格求解全部开放空气：

- 气体区域节点保存可用体积、组分库存和近似均匀压力；
- M5 使用固定参考温度的简化状态方程，M9 再加入内能、动态温度与非等温过程；
- 外界大气是带参考压力、温度和组成的特殊环境节点；
- 门缝、小孔、管道和大开口作为连接边，流量由压差、面积和阻力决定；
- 打孔不会瞬时删除高压库存，扩大开口只提高有限均压流量；
- 区域分裂按原密度/温度和子体积分配库存，合并保持总库存与能量；
- 液面压缩气体时更新可用体积，并把气压作为液体自由面的边界压力；
- 只有喷流、火焰或玩家附近确实需要空间速度场时，才局部展开为细网格；首版可显示方向性喷流粒子，但不能声称已解析湍流。

### 拓扑预算

控制器域直接使用已知边界。未来天然空腔的增量 flood fill 默认最多访问 512 BV，并受服务器总预算约束。触达未加载边界、环境连通标记或硬上限时，立即分类为连接环境大气并停止；不得扫描整片洞穴或地表，也不得把超预算空间保存为有限密闭库存。

方块更新只标脏相邻节点与边。状态和 debug 必须报告访问量、停止原因和最终分类。

区域节点与压差流路可参考 [NIST CONTAM](https://www.nist.gov/services-resources/software/contam) 及其 [气流路径说明](https://nvlpubs.nist.gov/nistpubs/Legacy/IR/nistir7251.pdf)。

### 验收

1. 开放水面使用环境表压。
2. 密闭液面压缩空气时，压力随可用体积单调增加。
3. 高压腔通过小孔在有限时间均压，不瞬时归零。
4. 开孔、封孔、分裂与合并保持气体库存。
5. 两侧气压差能维持重液柱的不同高度。
6. 气体混合与未来气相反应复用 species 库存。
7. 超大空腔边缘更新不超过单 tick 搜索预算。

连续开孔/封孔不得产生瞬时压力 NaN，也不能因拓扑重建重复或删除库存。

边界继续有效；冲突时以该正式架构契约为准。

Godot 参考的二维沙粒支撑链和经验孔隙排水不能直接成为最终三维模型。首个原型只承诺：

- 颗粒携带材料 ID、体积、质量、速度与反应属性；
- 水中受重力、浮力和相对速度阻力；
- 真实固体体积从流体可用体积扣除，孔隙水仍参与压力；
- 颗粒碰撞半径可小于液体 marker，压力格保持当前分辨率；
- 稳定堆积超过阈值后聚合为沉积格并休眠；
- 沉积格保存材料 ID、精确数量、孔隙率和必要的混合组成；
- 只有局部扰动或反应唤醒必要数量，不因普通支撑变化全量粒子化；
- 反应沉淀与沙共用运动机制，但材料、颜色、密度和反应规则独立。

颗粒排开的精确水量来自真实固体体积，不能从平滑 density 估算。低成本模型必须同时通过沉降速度、轻重颗粒浮沉、安息角、孔隙水压力、密闭容器总体积和沉积/再溶解守恒。若无法满足，先做小型 MPM/Drucker–Prager 验证；不得继续堆叠支撑、吸附或偏置经验规则。多相 MPM 方向可参考 [Pradhana 的水沙研究](https://escholarship.org/uc/item/52b8b82q)。
