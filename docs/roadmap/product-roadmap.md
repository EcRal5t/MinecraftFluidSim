## 发布切割线

- **1.0**：完成 M3 多液体/可变密度、M4 表面张力/润湿、M5 密闭气体网络与气液压力。范围仍是控制器或开发命令圈定的有界区域；这是首个可独立发布维护的产品终点，不是临时演示版。
- **2.0**：从 M6 ownership 评审与真实世界流体桥开始；未通过 M6.0 的事务/恢复门，不扩大 takeover。
- M7 化学、M8 颗粒、M9 热力学和 M10 原版/其他 Mod API 在 2.0 后逐项加入，不阻塞 1.0。
- 版本号按实际验收门决定，不随开发次数自然表示成熟度。

## 长期产品目标

1. 一个方块空间可包含任意体积、组分和相态，不受原版“一格一种流体”限制。
2. 可互溶液体连续混合；不可互溶液体共享机械压力但保留界面并按密度分层。
3. 开放空间使用环境大气；密闭空间保存有限气体库存和压力，小孔以有限速率连通。
4. 材料、相和反应数据驱动；所有源汇之外守恒质量、组成、电荷、体积和后续能量账本。
5. 颗粒阶段只覆盖沉淀、细沙等低成本沉降/沉积，不承诺通用刚体或弹性固体。
6. 先在有界工业区域达到可靠、可恢复和可量化，再评审河流、海洋和开放世界接管。

近期不做：逐格求解所有开放空气、逐分子/离子粒子、首版弱酸/缓冲液/活度/动力学/完整化学平衡、通用刚体/弹性体、无界天然洞穴扫描、海洋规模 20 Hz 承诺。M3 不提前实现有限溶解度或表面张力，但必须保留后续数据边界。

## 必须长期保持的分层

- **物理真值**：marker 体积，未来再加材料质量、组分、电荷、气体量和能量账本。
- **数值离散**：压力、PLIC、cut-cell、组分输运和曲率；不能反过来结算物理库存。
- **渲染重建**：客户端从只读快照派生外表面、液液界面和颜色。
- **调度策略**：活动/降频/休眠/卸载/CPU-GPU 后端不得改变守恒结果。
- **世界事务**：任何 ownership 或原版方块替换都必须先有可恢复的原子发布状态。
- **协议/存档**：protocol、takeover journal 与 region-state 独立版本；未知格式必须明确拒绝。

## 目标数据边界

- material registry 定义密度、黏度、颜色、相态、互溶组和未来热/化学属性。
- marker 携带相/材料身份与守恒质量；单一纯水应严格退化为当前 `particleVolume` 解。
- 稀疏 mixture handle 只在多组分格存在，不为每个 marker 复制完整组分 map。
- 不可互溶相共享压力/速度框架；模型不能声称已解析界面滑移或乳化。
- 客户端 palette/界面字段是展示数据，不成为材料库存。
- 世界、bucket、region、checkpoint 和网络单位必须显式换算，不能用渲染 density 充当库存。

## M3：多液体、可变密度与连通器

按 KISS 分三步推进：

1. 冻结最小 marker 材料/相标签和质量账本，保持独立 CPU 状态，不改 protocol、存档或世界交互。
2. 建立同密度两材料严格退化为当前纯水解的一个 3D 连通器门。
3. 在同一独立 3D column 接入已选的 interface-distance-weighted conservative `1/rho` 面系数，覆盖 1.25:1 与 13.6:1。

通过上述前置后，才依次加入 registry、互溶组、不可互溶分层、多材质快照和 partitioned marching tetrahedra 内部界面。完整桶矩阵留到 M6.1。

完成条件：同液 U 形管等高，不同截面连通器静水平衡，不同密度液柱压强匹配，油水翻转后稳定分层；质量/体积守恒，外表面与内部界面可见且不重合。

## M4：表面张力与润湿

- 数据驱动液气/液液表面张力和固体接触角。
- 使用界面曲率与 balanced-force 压力跳跃/体积力，不写死吸墙或浅水聚集。
- 覆盖静滴压力跳跃、无持续伪流、合并/断开守恒、不同接触角铺展。

完成条件：不得以墙角偏置、受支撑强制找平或渲染收缩替代表面张力。

## M5：空气区域网络与气液压力

- 环境大气节点、密闭区域识别、区域分裂/合并与有限开口边。
- 保存气体组分库存；液面体积改变更新气体可用体积，气压成为自由面边界。
- 控制器域使用已知边界；未来天然空腔搜索默认最多 512 BV，触达未加载/环境/预算即停止。
- 覆盖小孔/大开口有限均压、开孔库存守恒、汞柱和气液耦合。

完成条件：达到有界工业系统 1.0；不扫描整片洞穴或逐格求解开放大气。

## M6：世界 ownership 与流体桥

### M6.0 设计评审

- 最小原型比较代理占位方块与“空气 + 独立 registry”。
- 评估方块机制、其他 Mod 可观察行为、失配恢复、存档成本和玩家编辑。
- 冻结 ownership、region-state、原版方块替换和解除接管的共同代次/恢复状态机。

完成条件：选择一条路线并记录拒绝另一条的证据、格式风险和迁移方案。未通过不得进入 M6.1。

### M6.1 世界桥与容器

- 实现纯材料满桶、部分桶、混合物容器和合并配方。
- 覆盖玩家、发射器、合成、漏斗、掉落/死亡、创造和其他 Mod 行为矩阵。
- 按 chunk 持久化 ownership 水；先让其真实流动，再适配灭火等原版行为。
- 扩大范围必须显式配置、可恢复，且不覆盖玩家实体方块。

## M7：守恒化学

- species/phase/reaction codec、稀疏组分库存和硬上限。
- 强电解质完全解离、同格计量反应、游戏化 pH 与指示剂。
- 每步质量、声明组成、电荷和液体体积账本闭合；颜色只在客户端派生。

首批验收：NaNO3+KCl 与 NaCl+KNO3 得到相同离子库存；HCl+NaOH 中和且过量物正确剩余。

## M8：颗粒沉淀与低成本沉积

- 数据驱动颗粒材料、浮力/阻力、孔隙和精确排水。
- 安息角、沉积休眠、反应沉淀与局部唤醒。
- 低成本模型不能满足守恒/形态门时才评审 MPM，不预建完整框架。

## M9：温度、相变和反应热

- 引入内能与热容量，温度作为派生量。
- 热输运、固体换热、相变、反应热和气体压缩/膨胀。
- 绝热系统总能量闭合；相变前后质量/组分守恒；热休眠与速度休眠分离。

## M10：原版行为与其他 Mod API

- 灭火、湿润、岩浆反应、红石、生物和寻路逐项适配。
- 提供材料注册、容器传输、区域端口、查询和事件 API。
- 外部 API 必须声明单位/映射，不得直接修改平滑 density 或客户端 mesh。

## 性能与停止条件

- 活动成本应随扰动表面积/活动 section 数增长，而不是随整个库存线性增长。
- 平静区域要能进入守恒休眠；扩大范围前代表性静态测试至少 80% 体积可休眠。
- 世界读取/修改留在服务器主线程；数值后端只消费不可变输入并在 tick 边界提交完整代次。
- GPU 常规步只回读紧凑诊断/快照；完整状态仅在 checkpoint、卸载、迁移或诊断时分片回读。
- 超时保留上一完整状态，不展示半步；CPU 始终是规范和回退。
- 32³ 方块 GPU 目标必须有真实报告，否则据实降低默认上限。

若阶段失败，依次缩小活动区、降低更新率、采用宏观节点/沉积状态，最后才降低空间分辨率；不得先牺牲守恒或用渲染隐藏失败。

## 验证策略

验证按风险升级，不是累计清单。日常小增量只跑 [`../maintenance/routing.md`](../maintenance/routing.md) 指定的一项最近门；里程碑关闭时再按 [`acceptance-and-release.md`](acceptance-and-release.md) 汇总实际受影响的层次。

## 接下来三项

1. 冻结最小 material registry、互溶组与不可互溶相状态，并用独立 CPU 门验证质量/体积/动量输运。
2. 将已经通过 1:1、1.25:1 和 13.6:1 的 3D 算子接入活动核心，先证明纯水严格退化，再做不同截面与翻转分层。
3. 活动核心门通过后再评审 protocol、`region-state` 与多材料快照迁移；未完成评审前不写入正式世界数据。
