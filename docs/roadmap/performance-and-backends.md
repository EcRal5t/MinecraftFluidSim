# 性能、调度与计算后端规格

本文保存未来扩容与可选加速后端的约束。当前 GPU probe 的实现和实测结果属于历史证据，见 [M1 报告](../progress/m1-gpu-probe-report.md)；这里不重复版本流水账。

## 规模事实

当前 `24×16×24` 求解网格为 9,216 cells，满水约 73,728 markers。`32×32×32` 方块按每轴 2 cells 计算为 `64³ = 262,144` cells、约 2,097,152 markers，是当前规模约 28.4 倍。开放世界显式填充空气远大于此，因此扩容必须同时依赖稀疏活动区、休眠和可选加速。

独立测试上限、当前 manager 预算和未来产品容量是三个不同概念。任何扩大都要分别配置单区域与全服 cell、marker、组分、网络和设备内存硬预算。

## 活动等级与守恒

- `ACTIVE`：完整子步、压力、粒子、反应和耦合。
- `REDUCED`：保留完整真值，以较低频率更新，边界 guard band 保持全精度。
- `HYDROSTATIC_SLEEP`：保存静水/分层宏观状态与精确库存，速度承诺为零。
- `UNLOADED`：完整状态已验证落盘，不占求解数组。

不得只跳过 advection 却继续从旧 marker 位置 P2G。相邻不同等级的质量、动量与压力通量必须成对记账。扩大范围前，代表性静态测试至少应有 80% 体积可进入守恒休眠。

## 并发边界

Minecraft 世界读取、方块修改和实体快照留在服务端主线程：

1. 主线程冻结本步碰撞、边界和交互输入；
2. CPU 工作线程或 GPU 只消费不可变输入并写下一代；
3. tick 边界只提交完整结果；
4. 超时继续保留上一完整代次，不展示半步；
5. 所有世界修改仍由主线程事务执行。

调度与连续超时保护以 wall time 为真值。设备 timestamp 只是性能观测。

## 生产 GPU 后端边界

- CPU 始终是物理规范、兼容回退和存档重建来源。
- 粒子、网格和临时求解向量应常驻设备内存，常规步不能全量回读 JVM heap。
- 快照周期在设备侧压缩表面/分相字段、marker/solid mask、palette 与诊断，只回读紧凑 payload。
- 桶、实体和方块交互使用有界查询，不以读取全部 marker 为前提。
- 完整状态只在 checkpoint、休眠、卸载、后端迁移或诊断时异步分片回读，并用代次防止跨步拼接。
- 初始化失败或运行时设备丢失时，暂停受影响区域，从最近 CPU 可读检查点恢复；不能继续使用不完整缓冲。
- GPU 浮点不要求逐 bit 等于 CPU，但必须满足相同守恒与误差上限。

生产接入前需重新回答：CPU/GPU break-even、压力求解质量、常规/完整回读成本、64³ 容量与 20 Hz 可行性、Minecraft 同时渲染的长期稳定性。M1 probe 证明能力，不自动选择生产后端。

## 停止与降级顺序

阶段不满足预算时，依次缩小活动区、降低更新率、采用宏观节点或沉积状态，最后才降低空间分辨率。不能先牺牲守恒，也不能用客户端 mesh 隐藏数值失败。
