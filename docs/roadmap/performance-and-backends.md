# 性能、调度与计算后端

本文说明性能测量方法和后续生产 GPU 的要求。定位实现看 [性能路由](../maintenance/routing.md#performance)，复现命令与当前 CPU 耗时指标看 [验证指南](../maintenance/validation.md#performance)。

## 当前规模与调度

默认网格单元边长为 0.5 m，`24×16×24` 网格有 9,216 个单元。若扩大到 `32³` 个 Minecraft 方块，则需要 `64³ = 262,144` 个单元。扩展时应分别预算单元、粒子、化学载体、沉积、网络消息和设备内存，并同时设置单区域与全服务器上限。

当前 CPU 单步超过 40 ms 后按 1–4 tick 间隔执行，连续三步超过 200 ms 会暂停。降频、休眠和卸载保持完整库存。一个被执行的力学步仍包含完整的速度传递、压力和位置推进，阶段顺序见 [流体求解器](../architecture/fluid-solver.md)。

方块、实体、容器、反应、温度梯度和气压变化唤醒受影响区域。扩大默认范围前，代表性静态场景应至少有 80% 体积进入休眠，观察操作保持该休眠状态。

## 先测量哪些成本

1. 粒子到网格、压力、网格到粒子和位置推进。
2. 导热、反应、相变与颗粒处理。
3. Minecraft 碰撞、实体和世界交互。
4. 快照编码、网络发送和设备回读。
5. 存档捕获、压缩、回读验证与恢复。

报告记录区域尺寸、活动粒子和载体数、子步数、PCG 迭代与残差、GC 和实际耗时。GPU 内部执行用设备 timestamp 测量，调度仍使用实际经过时间。

[ProductionFluidReplayValidation](../../fabric/src/test/java/cc/ecisr/mmm/simulation/ProductionFluidReplayValidation.java) 的 `defaultLiveStepsRemainBounded` 覆盖默认控制器和最大装量开发场景。JVM 预热单独报告，被测场景保持完整物理能力、原有阈值和每步收支校验。

当前 CPU 已减少三类重复开销：精确数量的重复求和、候选状态的序列化往返，以及同次压力投影中反复构造矩阵。继续优化时对照原输入和轨迹，记录子步、PCG 与相变事件，确认改动只消除了重复工作。

## 有限体积输运的生产资格

单元有限体积输运已经通过空间分布、逐格容量及完整物理收支校验。原有 `production-live-budget` 中的小控制器负载通过 40 ms 限制，最大装量溃坝仍连续超过 200 ms，保持默认关闭。完整步的载体输运、网格传递、热学与候选恢复共同决定成本；后期超时持续发生在无需时间细化重算的步骤中。

当前串行 CPU 路径的局部优化到此结束。继续取得显著收益需要并行数值执行、连续载体布局与工作区驻留，性能工作转向下面的生产 GPU 后端评审。CPU 继续维护守恒、有效域和故障处理，作为对照及恢复后端。GPU 的实际收益、完整能力和交接成本均须独立证明，通过原有预算和默认构建的联合校验后再启用有限体积输运。

## 并发计算与提交

未来 worker 或 GPU 后端沿用 [运行时专题](../architecture/runtime-and-lifecycle.md#candidate)的交接过程：

1. 服务器主线程捕获完整 `FluidDomainState`，请求绑定当前代次。
2. 后端在私有状态上完成计算，返回完整候选结果。
3. 提交前重新检查后端、代次与布局，成功后一次替换区域状态。
4. 超时保留上一完整状态；世界和物品变更由主线程事务处理。

同进程 CPU 可以直接交接已算好的私有对象，且只交接一次。其他后端可以返回不可变状态。所需完整性由数据内容和检查规则决定。

## 生产 GPU 的完成要求

| 方面 | 要求 |
|---|---|
| 物理能力 | 完整支持 `FluidDomainState` 中的材料、变密度、表面张力、气体、热学、化学、颗粒和相变 |
| 常规计算 | 粒子、网格与临时向量常驻设备，快照在设备侧压缩，按需回读表面和诊断 |
| 完整状态 | 保存、卸载、切换后端、重放或诊断时，按代次生成完整状态或分片回读 |
| 故障恢复 | 设备丢失后暂停区域，从最近 CPU 可读的 checkpoint 恢复 |
| 正确性 | 满足同一库存守恒规则与数值误差上限，CPU 继续作为参考与恢复后端 |
| Minecraft 接入 | 服务器主线程保留世界、物品和存档提交职责 |

评审应给出 GPU 开始优于 CPU 的规模、压力求解质量、常规与完整回读成本、`64³` 容量、20 Hz 可行性，以及 Minecraft 同时渲染时的稳定性。

## 当前 probe 已验证的部分

独立 kernel 已验证 Vulkan、Shaderc、VMA 和计算提交，checkpoint 可将 GPU 的整格固体标记转换为 CPU 的完整碰撞微网格标记。

CPU/GPU 共同支持的部分采用相同的守恒速度传递、`H(div)` 平流、碰撞和 float 粒子合并规则。1000 步长跑用逐粒子的精确二进制数量核对库存，GPU 并行求和用于带舍入误差范围的在线诊断。

当前 probe 只有单一常密度载体。上表列出的完整材料与热化学能力、生产存档、回读和恢复接入仍待实现。完成这些工作后，才能评审它作为生产求解后端的表现。

## 超出预算时怎么处理

依次考虑缩小活动区、降低更新频率、采用稀疏气体节点或沉积表示，最后评估降低空间分辨率。每次调整都重新验证守恒、可观察误差和性能，具体范围扩张要求见 [验收与发布](acceptance-and-release.md)。
