# 性能与 GPU 后端参考

生产区域使用 Vulkan 常驻状态和设备候选。宿主负责世界输入、库存编辑、事务和显式 checkpoint。范围扩张与物理能力目标见[产品路线](product-roadmap.md)，当前工作见[实施计划](solver-consolidation-plan.md)。

## 测量与提交

完整步计时覆盖输入捕获、设备计算、提交和必要的世界效果；编辑与存档分别记录回读、宿主规划和写入成本，冷初始化单列。比较使用相同硬件、输入、功能和物理时长。单步超过 40 ms 后按 1–4 tick 间隔推进，连续三步超过 200 ms 暂停。64³／50 ms 是待评估目标。

设备请求使用完整私有候选，应用层检查区域身份、输入代和布局后采用。失败候选释放，已提交代保留。设备丢失时暂停区域，按 HEAD 与 WAL 恢复外部事务，再从一致 checkpoint 重建状态。观察只读取需要的设备摘要；保存、恢复和编辑明确捕获完整代次。同布局编辑复用候选槽和资源，记录导入范围与所需重算。

## 生产 GPU 的完成要求

设备推进覆盖材料、液气固占容、动量、热学、化学和相变状态，按实际整数库存及能量账验收；数值近似以容量、守恒、宏观现象和适用尺度衡量。设备候选、WAL 和 HEAD 必须支持已发生世界／物品效果的故障恢复。各阶段使用同一活动组输入，布局声明为宿主与 shader 提供共同字段编号。

命令、预算和最新证据见[验证指南](../maintenance/validation.md#当前验证证据)。只读 [GPU 执行原则](../architecture/gpu-execution-principles.md)记录设备调度设计依据。
