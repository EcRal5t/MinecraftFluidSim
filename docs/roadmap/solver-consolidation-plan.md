# 当前实施计划：求解器整合

目标是可玩、符合直觉物理、具备工业仿真特色且架构精简的流体 Mod。本文保留当前交付状态与遗留事项。

本页只保留当前工作、未完成项和完成条件，随实际发现调整方向。已实现模型与代码入口见[设计书](../architecture/system-overview.md)，命令、预算和实测见[验证指南](../maintenance/validation.md)，长期功能安排见[产品路线](product-roadmap.md)。历史交付与淘汰方案留在 Git。

## 后续工业玩法安排

[自由构造工业玩法后续实施计划](emergent-industrial-gameplay-plan.md)规定 P0—P6 的近期范围：沿既有性能主线，依次交付抽象物料箱与持续进出料、可控阀门和测量控制、世界方块与原版活塞适配、筛分、固定表面吸附与催化，以及三维组合工艺。运动耦合承担实际表面速度、可反馈惯量、冲量和机械功；机构与驱动复用原版或外部 Mod。

本轮编制计划与[三维装置测试规格](industrial-simulation-test-plan.md)，实现保持当前状态。新场景按依赖分批加入现有算法及功能测试，包含连续流控制、活塞泵送、筛分结晶、换热、蒸馏、吸附再生和接触催化。近期数值工作继续优先完整步耗时、颗粒场景和长流程尖峰；各阶段实施时在本页维护进度，运行证据写入验证指南。

## 仿真能力补全

[能力补全施工计划](simulation-capability-completion-plan.md)中的 S1—S8 已贯通功能、正常工艺、宿主编辑与保存恢复。材料属性统一来自世界数据包，生产推进统一使用 Vulkan。当前交付已整合原 64³／0.5 m 完整生产步的计算、提交和显存路径。RTX 5070 Ti 的最终测量受 NVIDIA 驱动初始化故障阻断，50 ms 目标保持未完成；恢复驱动后继续同一输入的完整步验收与必要优化。性能及正常流程证据统一登记在[验证指南](../maintenance/validation.md#simulation-capabilities)。

液体、逐格气体和实体占容共用 MAC 面、局部状态方程与实际接受通量。共同压力采用有界迭代预算，流体出流采用守恒的有限驻留时间近似，普通流体按完整请求时长推进一次。粗格高速流动会减慢传播，压力保留有限解析误差；质量、物种、携带内能、动量及机械热仍按同一份实际交接量结算。运动固体沿真实开放面完成关闭格排空，必要时按请求时段插值姿态。旧的流体全域 CFL 重放及压力迭代宿主续批路径已删除。

共享 PLIC 几何提供相占容、湿壁面积、有效壁距和热接触。普通固壁使用无滑移，有限墙保存独立热库存；混合黏度、热容、导热及扩散携能按实际组成求值。液体热胀采用浮力近似，库存保存参考体积。同相有限扩散、Henry 传质、水／乙醇理想挥发平衡、温度相关溶解度和颗粒有效面积复用共同库存与能量账。竞争、可逆有限反应与快速解离、中和共用局部计量网络。

同一区域采用固定 8³ 稀疏计算块、紧凑单元列和唯一 MAC 面。压力、输运、黏性、扩散、热学、颗粒及实体使用同一拓扑；块哈希、直接邻接和多重网格父子映射随布局建立。所有块统一采用候选并保存 HEAD，恢复按稳定空间坐标重建紧凑索引。物理连通组共同暂停和恢复，暂停组精确保留库存、内能及面动量。区域成员在创建时确定，动态扩容与独立区域合并仍属后续产品范围。

设备候选通过并行复制计划交接明确的持久字段与有效派生状态；相转换共用液相候选行，各算子分别保存实际能量账。热化学复用输运后的接触几何，提交前集中更新最终相形状。状态方程保存与步长无关的压力顺应性，压力装配时应用当前时长；同代有效的热状态和几何可直接复用。工作区统一释放复制计划和命令资源。

两级 0.5 m／1 m 网格的研究已完成，方案与取舍见[两级空间分辨率](../architecture/fluid-solver.md#两级空间分辨率)。粗细交界需要共享子面、同一压力求解和守恒重映射；细小碰撞几何还需保留更细的几何采样。当前交付继续使用统一格长，将两级自适应留作独立空间表示改造。

持续投料、有限墙加热、吸收脱除、晶种结晶、碱液碳化、规定运动驱动和干壁冷凝沿真实容器、端口、取样、停止、保存与恢复流程运行。冷凝使用独立冷段取样和相间来源账；普通墙随区域终态保存。宿主碰撞刷新采用一次守恒事务，先保留本格可容纳库存，再沿原开放面搬迁超量部分，并结算气体压缩功。材料密度、黏度曲线、热浮力、张力、接触角、显示属性、气体组成及溶液参数均由 JSON 提供，内置材料类只保留稳定标识。

优化以完整步耗时为首要目标，架构精简与算法泛用为次级目标。原 64³／0.25 m 机械切格和 32³／0.5 m 颗粒基准保留各自输入，完整生产配置使用正式支持的 0.5 m 格长。预算按实际驻留格数计费，报告完整时段的墙钟耗时、GPU 时间、提交次数和显存；冷导入、长流程尖峰及世界绘制分别登记。后续优化继续按完整职责链替换成本失控的算法。

## GPU 执行链主线化

[GPU 执行链主线化计划](gpu-mainline-execution-plan.md) 的 G1—G6 已落实。生产时间推进统一使用 Vulkan；宿主负责初始化、有限库存编辑、世界事务、状态编码与恢复。设备候选按代次采用，普通查询与展示读取设备摘要，存档显式捕获完整状态。CPU 完整求解、混合压力、宿主热学和气孔流时间推进已删除，`HostFluidState` 保存编辑与恢复所需状态。

活动组按同代物理连通关系传播区块可用性；机械、独立热轴和手动单步共用活动输入。暂停组保留各相库存、内能、动量、实体占位和未决相变任务。环境温度更新直接写入设备候选，同布局库存编辑复用候选槽；设备失效暂停运行，按 HEAD/WAL 恢复已发布事务。生产代码与无头验证源码已分离，GPU 阶段的布局常量由宿主声明生成，压缩 shader 已展开。

shader 命名覆盖压力、输运、热学、实体、气体、颗粒、相变、化学、机械能、几何、观察与展示内核。主要物理量、存储索引、归约字段和阶段按职责命名，共享 GLSL 函数与引用方同步。

主线审阅中的状态交接问题已修复：卸载清理有限热设备缓存，完整区域 tick 统一处理设备失效，实体目标姿态参与扫掠分组后再筛选，容器预览与执行继承当前活动组可用性。验证源码哈希覆盖 GPU Java、shader 及构建配置。 设备预热失败采用与创建失败相同的暂停处理；导入即时准备热显示派生，局部转移按相关可用组检查相变任务，实体请求预算在活动组筛选后检查。验证入口为生命周期、容器、区域存档与 GPU 完整水流流程。

S1 交接复审已分离几何缓存与气腔分组摘要有效性，机械阶段事件按实际执行结果读取；同柱多层床面分别参与起动与松弛，全加载宿主规划建立当前物理分组。能力配置明确化学与相变依赖，缺失气腔在 GPU 导入时统一准备。相关回归及支持范围见设计书和验证指南。

G3 宿主编辑由 S2 的局部液气事务接管，后继沿现有设备候选与持久交接采用。

实体扫掠和颗粒占容进入共同孔容及面惯性，库存沿真实开口迁移。局部液气压力、占容与压缩功使用同一状态方程。运行证据及限制统一见[验证指南](../maintenance/validation.md#当前验证证据)。

2026-10-28，本轮按完整游戏操作职责链交付 GPU 演示。主模组默认使用 Vulkan，保留世界能力、实体耦合及连续三步超过 200 ms 暂停的规则。日常演示采用便于观察和操作的小场景，原大型溃坝及性能输入独立保留。

已贯通场景初始化、调度、设备推进、常规观察与展示快照、宿主恢复、库存编辑和再次推进。控制器使用真实端口及容器 WAL；capture/takeover 复用采样、持久日志和恢复事务。演示与自动化共用初始化和操作逻辑，物理验收检查溃坝流动、油水分层、酸碱及生成水的当量、气压液位响应和相同初态的润湿差异。

气液通量、局部压缩功及相几何按同代库存共同结算，环境交换和相间转移分别记账。质量与元素按整数守恒，能量使用工程浮点误差范围；常温场景同时检查实际温度变化。

求解程序在世界启动阶段准备，区域编辑后的重导入复用编译与管线缓存。原 64³／0.5 m 完整生产步使用 50 ms 预算，当前实测与完整流程结果统一登记。命令、逐场景结果、完整步耗时范围和当前产物见[验证指南](../maintenance/validation.md#gpu-演示完整流程)。实机视觉、复杂 VoxelShape 与跨游戏重启仍按下列人工范围安排。

控制器界面与服务端交互已统一：普通玩家可暂停和继续；管理员在暂停后预览清理及移除；异步响应按目标和请求代次更新当前页面；空的气腔几何允许释放与移除。自动化覆盖协议、生命周期、GPU 容器操作及持久清空／排气／删除；实际窗口布局与输入观察保留在游戏内验收范围。

高浓度析盐已贯通完整 GPU 推进：颗粒运动与形态转换按实际占容交接液体排水和气腔，机械能沿转换前的行身份结算；密集接触采用颗粒局部轨迹细分，保留生产耗时暂停。恢复先接收相变待位移状态，颗粒位置及整数支持配额在设备与宿主之间保持一致。自动化覆盖连续析盐、带沉淀的待位移 checkpoint、恢复续算和清空，结果见[高浓度析盐验证](../maintenance/validation.md#高浓度析盐)。基础酸碱配方继续采用稀溶液观察中和与 pH。

## 演示与操作手感

`/mmm demo` 和快速入门手册打开统一演示面板。水箱、水流、气压按布局分组，提供开始、暂停、单步、原位重置、移除与显色设置。开始成功后返回游戏画面；失败时界面保留当前状态和原因。

水箱采用真实控制器与接口，内腔为 2³ 方块，清水、油水和酸碱配方复用同一区域。默认清水配方加入两桶水；配方先在私有候选完成清理、室温常压复位和实际容器投料，再提交现有持久化流程。水箱身份按玩家、维度保存；通过原控制台删除后，工作台读取已提交的删除记录，再清理原样壳体并重建。启动检查识别工作台存档及其临时文件；能力包无法确认时保留原文件并锁定区域写入。

原版水桶没有热数据时按标准温度准备源库存，已有热数据的容器沿自身内能交接；物品原态与源库存共同进入容器事务。创造模式投料保留源物品，取出返回携带库存与内能的容器。

水流池包含可见池壁、绕流障碍与入池台阶，继续测试玩家排水。气压场景使用小型 U 形管，左臂封闭、右臂通大气，下方水体连通；常压、加压和低压共用初始液位，直接比较两臂升降。气压管关闭实体耦合，玩家排水由水流池展示。原材料与化学命令改为水箱配方快捷入口；大型溃坝移至 `damdemo`，采样／接管和毛细实验保留独立诊断入口。后续颗粒与热设备演示按玩法需要另行选择。

自定义界面的标题、状态、摘要和错误文字统一使用不透明 ARGB；显色选项直接标记当前模式，温度输入随温度模式显示。

2026-10-29，修复 Minecraft 26.2 图集定义 ID 与纹理 ID 混用造成的客户端崩溃，空颗粒及诊断显色按需生成顶点。演示请求状态机已可无头驱动全部七个预设；首次放置失败允许换位置重试，跨类型切换先检查新位置与区域占用，暂停失败返回真实结果。控制器失败回复会结束界面等待并显示原因，刷新与缩放保留滚动和未提交输入。验证范围见[交互自动化](../maintenance/validation.md#演示与客户端交互自动化)；窗口和实际绘制继续保留实机观察范围。

极小液量采用紧凑角部 PLIC，零体积裁剪片不参加表面、邻面遮挡或相机介质判定。GPU 容量配额预留分数量子，原地余量可随供体排空完整交接，消除反复取整造成的悬空残留。客户端在原版透明地形前提交水面，并统一材料、颗粒和阴影的相机锚点及 Iris 方块中心坐标；跨批次透明排序仍有支持限制。自动化证明几何面积与库存尺度相符、微量液体实际下落；真实画面质量仍待观察。
