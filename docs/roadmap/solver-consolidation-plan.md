# 当前实施计划：求解器整合

目标是可玩、符合直觉物理、具备工业仿真特色且架构精简的流体 Mod。当前集中完成 GPU 常驻后端，先解决完整步耗时。

本页只保留当前工作、未完成项和完成条件，随实际发现调整方向。已实现模型与代码入口见[设计书](../architecture/system-overview.md)，命令、预算和实测见[验证指南](../maintenance/validation.md)，长期功能安排见[产品路线](product-roadmap.md)。历史交付与淘汰方案留在 Git。

## 当前重点：GPU 完整步

**完整 GPU 后端、原64³完整步20 Hz及同场景十倍提速均未完成。** 当前保留真实上风PLIC、共同压力、同容量量子材料分份和精确库存交接。容量撤回已改为活动队列及增量余额；气体组分与允许物种固定寻址；液体汇集直接写入精确体积，删除中间求和扫描。原64³连续15步复用完成的物理面并缩短容量执行链后，最新中位52.754 ms、最大77.450 ms、GPU平均44.309 ms，完整步仍无性能资格。原49轮容量输入降至GPU5.902 ms，长尾传播与后续压力成本仍须按整步处理。现有设备、颗粒、热化学及生产交接实现按实际调用链复用。压力预条件器扩展保持暂停，下一步审视细层算术与内部求解表示；集中物理验证后置。

恢复工作、切换方案或准备交付前，读取[GPU 完整步重设计只读备忘录](../architecture/gpu-execution-principles.md)。用户已认可总体方向；执行顺序根据完整步成本和实际阻塞调整。

### 下一轮方向

- **先减少完整步必须做的工作。** 优先采用固定空间寻址、共享几何和面通量，复用静态邻接与求解层级；集中删除重复建图、库存重组和逐层主机反馈。库存位置与压力自由度分别选择，气腔聚合和局部半隐式气体按建表、求解与交接总成本取舍。
- **压力、容量与实际输运共同闭合。** 保留真实七路偏好、满液循环、固体排水和有限气体容量；区分连续残差与整数舍入。精确修正频繁重新路由全域大流量时，重新设计主要约束的处理方式。
- **先取得连续性能资格。** 原失败短重放用于定位与淘汰方案，随后回到原64³切格液气、容量、输运、孔流和导热整链，目标约35 ms，为剩余生产职责留余量。32³颗粒链同时评价；持续运行中的拓扑变化、刚性和扩容成本都计入。
- **性能允许后接齐生产职责。** 每接入一条完整职责链即测完整步；出现结构性超支时先处理成本。核心实现、调用迁移、正常流程和旧路径删除一起交付。

### 性能与完成条件

在 RTX 5070 Ti 上争取原64³完整步50 ms，并单独评价相同功能、输入、推进时长与精度下的CPU十倍提速。原场景、装量、时间步和既有预算保持；成本夹具与生产网格尺度的差异单列。新增功能必须实际参与综合负载，休眠或降频收益另列。

完整步包含准备、建表、求解、精确输运、热化学、提交及必要世界／展示交接。报告连续墙钟中位、尾部与最大值，以及GPU时间、提交／派发、全域通信、显存和回读量；CPU等待包含GPU执行，不能重复相加。短步或单项内核达标不能代替持续成本，最终还需评价与Minecraft渲染共用GPU的表现。

已有功能约35 ms是工程分配目标，完整交付以全功能成本判断。若目标不可行，结论须明确硬件、功能、精度和规模，并由完整链必要成本及替代方案证据支撑；合理降低规模或频率由用户决定。

构建与GPU测量串行安排，复用构建产物；委派仅使用 `gpt-6.1-sol`。保留工作区未提交实现，按实际职责决定复用或淘汰，适时提交完整成果。

## 精度与物理取舍

| 领域 | 保留的要求与允许的近似 |
|---|---|
| 物质与容量 | 质量、物种、反应批次和精确库存按共同数量规则交接，最终库存满足真实占容；完全排空携带尾数 |
| 几何 | 浮点重建、单元尺度形状与内部空间表示可替换；支持尺度内的隔墙、液封和真实通路保持一致 |
| 动量与流动 | 质量和动量使用一致通量，内部冲量成对结算，外部反力明确；惯性、旋转、冲击和分层按可观察误差评价，亚格细节允许耗散 |
| 气体 | 从库存、实际容量和内能派生状态，保持有限孔流及压缩／膨胀响应；均压近似的改变须说明玩法影响 |
| 能量 | 内能、压力功、反应热和潜热明确交接，耗散有实际去向；精确热账、浮点舍入与离散机械误差分别处理 |
| 事务 | 完整私有候选、一次采用、失败保留原状态，以及HEAD/WAL跨域恢复职责保持 |

选择能满足玩法的最简单离散。允许整体替换内部算法、工作区和模块划分；误差要求随解析尺度与可观察量确定，避免为单个失败样本反复放宽阈值。稳定公式与数据契约由设计书和专题维护。

## 验证与工作量控制

先让耗时达标，再做集中物理验证。性能开发期间只保留识别失效所需的库存、容量、有限数值和实际活动量观测；有95%把握的内容不重复验证。未知风险优先复用既有失败短重放，修复后回到原连续场景。

原64³切格与32³颗粒容量输入继续保留。正式场景、命令、误差和预算统一在[验证指南](../maintenance/validation.md)维护，生产GPU完成要求见[后端参考](performance-and-backends.md#生产-gpu-的完成要求)。集中验收覆盖守恒、真实容量、宏观流动、热化学及故障恢复；视觉、复杂VoxelShape和跨重启交接才安排必要人工观察。
