# 求解器整合与维护改进计划

目标是降低一次修改需要同时理解和调整的代码范围，让压力、输运、气腔、颗粒和热化学共用明确的数据与提交契约。进度按完整流程能否持续运行、生产成本是否可控、重复规则和旧路径是否减少衡量。

产品顺序与物理完成条件以 [产品路线](product-roadmap.md) 为准；当前实现见 [流体求解器](../architecture/fluid-solver.md)，代码定位与命令见 [维护路由](../maintenance/routing.md) 和 [验证指南](../maintenance/validation.md)。保留 `api ← model ← solver ← app ← fabric`、完整私有候选、区域 HEAD 与跨持久域 WAL 的既有职责。

## 当前需要整合的部分

| 当前事实 | 整合要交付什么 |
|---|---|
| `PressureSystem` 按区域有无颗粒或连续固相选择压力路径 | 共用液体几何、惯性与发布规则，固体按实际耦合加入 |
| 压力读取湿几何，惯性来自载体，输运重建下一份载体 | 同一空间表示连续经过压力、输运、气腔更新和下一步重建 |
| 常速度平移已有保存形状，一般场后继尚未接通 | 选定能承接自身后继状态、规模有界的生产表示，再替换临时专用路径 |
| 具体编辑已有候选预检与版本绑定，仍有入口分别维护顺序 | 复用现有计划，集中维护来源校验、容量与热账准备、一次发布 |
| `FluidDomain` 父类共享状态，重映射流程跨多个助手 | 按稳定职责明确输入与输出，减少跨模块字段依赖和重复求值 |

M00 已完成正式短长入口与失败分类。M01–M08 有局部成果，完整液气循环、共同液固离散与生产成本仍开放；M09 已有去重和职责拆分，后续随每次生产整合验收。M10 最后核对同一构建的全部完成条件。

## 整合后的完成要求

1. 每个子步使用明确的来源状态、空间表示和速度结果；成功后继能继续完成下一次压力、输运与气腔更新。
2. 精确库存、数值几何和展示数据各有明确含义。空间近似、速度舍入、重建耗散和表示转换误差分别量化，适用范围沿用产品路线。
3. 液体与气腔共用湿干几何、微盒归属及实际可达路径；同格多个气腔分别保存库存和内能，每节点压力功闭合。
4. 颗粒体积核、孔隙通量、压力反作用及液体位移遵循同一离散，预览、编辑、发布和恢复共用联合占容规则。
5. 支持范围内的注液、沉积、起动、反应与相变正常完成；拒绝候选保持原始列、账本、身份、组成句柄与待处理任务。
6. 每项生产整合同时交付被替换的重复规则、旧路径或共享可变依赖的减少，留下明确的排障入口。
7. 默认负载满足既有完整步预算：小控制器最大 40 ms，最大装量连续三步 200 ms；捕获、重建、求解和提交共同计时。

## 当前执行增量

### 表示与成本决策

当前先完成一次**累计最多两小时**的表示与快速成本检查，沿用真实 L 形输入及原注液失败状态。切换会话、细化任务或更换候选均计入这次检查的投入。开始前固定输入、对照与计时范围；到期交付可行性结论和下一段有上限的任务。

1. 比较现有表示与候选表示如何保存库存、湿区、来源及运动信息，列出需要替换的代码路径。共同运动网格是候选之一；选择依据是完整循环、可观测误差和规模成本。
2. 在隔离入口验证来源、到达与剩余片区的正覆盖及唯一分配，联合核对最终数量、接收容量、质量第一矩、线动量、角动量与可用动能。原输入的剪切、伸缩、旋转和 L 形后继共同约束方案。
3. 测量几何、数量分配和机械拟合，报告片区数、节点数、精确回退次数及随步数和输入规模的增长；结合现有完整步分阶段耗时，估算总成本与余量。几何及分配已超过 40 ms 的候选结束生产扩展；低于该值继续核对完整步预算。
4. 通过时选定一个方案，明确下一段连续循环的验收入口、预计投入与停止条件。成本或表示仍不可行时结束该候选的扩展，保留最小反例并比较替代表示；下一段投入根据比较结果重估。

全有理运动几何保留为独立对照。方案通过连续循环和成本检查后，再扩展形状存档及其他消费者。当前已接入的常速度形状保留回归，替换时同步清理对应分支。

### 最小连续循环与生产接入

选定表示后，用已有 L 形和原注液输入建立最小连续运行验证：实际压力求解、最终数量与坐标发布、气腔后继、捕获恢复及下一次压力准备均走实际调用路径。首个短运行就报告完整步时间、累计子步、节点与片区变化，持续覆盖产生一般速度场后的后继状态。

短运行成立后，立即恢复原注液场景的完整步数与断言，并扩展多轴、多出口、斜 PLIC、切格、组成和温度变化。每次扩展同时验收恢复、成本和对应路径替换。新状态必须能被下一步计算、编辑与恢复一致解释。

每段开始列出一项可交付的行为结果和一项维护收益，例如统一库存去向入口、移除独立到达规则或减少重复几何构造。临时并存路径登记适用范围、替换条件及所归属的下一交付；以调用者迁移和旧实现删除完成替换。

## M01 共同空间输入与状态身份

**入口：** `PhaseLiquidGeometryEdit`、`LiquidComponentMoments`、`PlicComponentGeometry`、`LiquidPressureGeometry`、`GasRuntimeGeometry`、`CellRemapMicroTopology`、`CellRemapPorts`。

- 固定连通分量、微盒和共享面采用规范身份；同格断开液体保留独立空间信息，未来编辑携带完整分量。
- 原始体积与质量分别维护第一矩，几何覆盖、孔隙内测度和载体积分分别核对。体积、质量与空间矩须能由接收空间的正数量表示。
- 压力湿面、气体干面和输运开孔读取同一来源的对应视图；明确位置、库存、组成、固体占容和碰撞改变后的失效规则。

**验收：** 重复生成身份一致，未来候选与实际发布后重建一致，过期来源在写入前拒绝；运动后仍满足相同契约。复用 `air-cavity`、`components`、未来几何和恢复容量对照。

## M02 速度空间独立验证

**入口：** `CellAffineVelocity`、`ExactCellAffineFit`、`CellAffineMacTransfer`、`CellAffineWallProjection`、`CellVelocityConstraintOperator`、`MarkerVelocityTransfer`、`MarkerPressureOperator`。

- 明确采样、面法向迹、惯性与压力行的对应关系；实际正质量提供惯性。单点、共线、近共面、薄层和断开分量分别检查可解析空间。
- 令 `B` 为载体速度采样、`D` 为体积约束，核对 `ker(B) ⊆ ker(D)`；实际采样秩与舍入后的 Gram 秩分别判断。所选空间保持常量、内部同步平移和三个刚体旋转模式、剪切及格内旋涡。
- 速度积分、体积第一矩变化与湿几何采用共同测度。完整湿块的零散度、零法向通量模式满足 `∫u dV = 0`；静水同时检查实际质量和几何压力功。
- 原始矩、几何矩和数值积分点各按其含义验收；正权节点须位于实际支持内，发布后的角惯性能承载输入动量、角动量与可用动能。几何近似明确误差，精度扩展记录触发频率与成本。

可表示性沿用原约束：归一化整格内 `Var(x) ≤ (.5−μ_x)(.5+μ_x)`；均匀密度、完整开放格的湿体积占比为 `V` 时，轴向质心满足 `|μ| ≤ (1−V)/2`，交叉矩同时受支持限制。最终正质量与位置形成角惯性 `I`，要求 `L−c×P` 可由它表示，且 `K_min = |P|²/(2M) + (L−c×P)ᵀ I⁺ (L−c×P)/2` 不超过可用动能；坐标与速度存储误差另行核对。

**验收：** 常量保持、`C t = 0`、内部 `C R = 0`、转置虚功、静水及稀疏相容性通过，并在 M01–M04 连续循环中保持。复用正式速度空间与压力核对照。

独立模型的表示或成本不成立时，先交付反例和方案比较。预条件与精度优化以共同模型成立、完整循环存在可行后继为前提。

## M03 液体与气腔压力生产接入

**入口：** `PressureSystem`、`MarkerPressureProjection`、`PressureProjectionStage`、`MechanicalStepPipeline`、`MechanicalStageAssembly`、`BodyForceStage`、`PressureBoundaryView`、`GridToParticleStage`。

- 同代几何与速度空间组装预测速度、气压、张力、壁面反力、液体约束和有限气腔储存；每份作用有一个明确施加位置。
- 气腔按实际接触微盒参与求解；同格多个节点分别保存库存、内能与压力响应，旧新几何交接保持实际可达来源和每节点压力功。
- 同一解生成载体速度、面速度与压力观察；发布精度、后续延拓和能量控制共同保持冲量、力矩、功与连续性。位置编辑、恢复和表示转换使旧场失效。

**验收：** 满液、部分充液柱、自由面、切格、同格多气腔及原密闭注液通过真实完整流程。微量气体、多轴多出口和可压缩库存分配通过；复用 `marker-pressure`、`gas-liquid`、静水、张力和候选原子性对照。

## M04 输运重建与速度交接

**入口：** `CellLiquidVolumeTransport`、`LiquidAffineFaceFlow`、`LiquidAffineSweepGeometry`、`ConservativeLiquidFlux`、`CellCarrierRemapPlan`、`BallisticLiquidRemap`、`FlipParticleReseeder`。

- 最终通量、供体扣除、到达与剩余库存来自同一正来源分配；面、棱、角的跨格去向共同核对，连续穿越多个面时保持来源唯一。
- 体积、材料质量、空间矩、动量与动能使用一致份额；species 整数量子、内能和最终 float 节点联合预检。体积第一矩的体积分与面通量积分使用同一子步测度。
- 覆盖零通量、双向交换、微量尾数、完全流出、进出抵消、独立粒子到达与切格排液；全流出核对剩余矩的存储舍入界。
- 整理输入汇总、分配、合并、采样及预检，复用已验证的机械拟合与库存发布，替换独立到达和支持修正规则。空间近似、重建耗散与写入误差分别观察。

**验收：** 零净面流率的剪切正确交换，未运动方向惯性保留，材料质心与三轴旋转误差有界；正温、容量、species、内能闭合；输运与 reseed 后可继续压力计算。复用 `transport-moments`、`joint-moments`、`components`、`chemical-tails`、`handoff` 和热输运，完整分层、断开分量长轨迹、长距离平移与 5,000 步场景用于包关闭。

## M05 液体与颗粒共同压力离散

**入口：** `GranularPressureCoupling`、`GranularImplicitDrag`、`GranularCoupledPressureSolver`、`SweptGranularVolumeGradient`、`GranularMechanicalStage`、`PressureSystem`。

在共同液体算子上加入实际颗粒惯性、核体积变化和阻力，保持同一预测状态与正定线性子问题。连续核、孔隙通量与压力力共用积分，覆盖外壳截断、核结点零预测速度、压力后反向运动和碰撞改道；先验证单颗粒完整循环，再接入多颗粒与有限气腔。deposit 与 coherent 按实际职责提供占容或附加响应。

**验收：** 内部同步平移保持相对静止，中性颗粒保持静水，液固总冲量与外部反力闭合，压力功和实际核体积变化一致；隔绝的远处库存保持目标液体的结果和离散选择一致。复用 `GranularCarrierValidation` 的压力、虚功、阻力和静水场景，完成按区域库存切换基础压力路径的替换。

## M07 活动颗粒与床层转换

**入口：** `GranularSettlementGeometryPlan`、`GranularInventory`、`GranularDepositDynamics`、`GranularBedPotential`、`GranularBedShear`、`GranularTransitionStage`。

颗粒云、骨架体积与床层转换保留质量分布；跨格联合沉积同时规划活动装填、床体和剩余颗粒合法位置。按来源及最终床层结算质量第一矩、势能、固定床冲量与耗散，起动抬升与液体做功成对准备，在首次固体写入前完成联合预检。

**验收：** 干式整桶沉积、湿沙沉降—起动—再沉积完成，平台、床层、混材与切格保持可达性；有空间和能量来源时正常转换，暂时受限任务可重试。复用沉积、混材松弛与 `GranularBedWakeValidation`，记录完成时间和停滞原因；必要局部耗散热随本包结算，全域热机械工作按产品路线安排。

## M08 反应与固液转移的空间信息

**入口：** `ChemicalReactionAllocation`、`ChemicalReactionStage`、`GranularReactionStage`、`GranularPhaseTransferEngine`、`PhaseChangeStageSupport` 及合并计划。

## M09 编辑计划数值运算与代码职责

**入口：** `CarrierMutationCoordinator`、`FluidDomainInventoryTransactions`、单格替换与注入/提取计划、`GasTopologyCoordinator`、`ThermalCellEnergyAssignment`、`ThermalCaloricInversion`、`ThermalDomainState`。

3. 将稳定业务迁到对应阶段或计划，显式提供所需视图；`FluidDomain` 保留状态聚合与完整交接。每次迁移同时减少调用者的跨模块字段访问。
4. 核对生产调用者并删除被替代路径，独立参考留在测试侧；同步更新现有路由条目。

**每次生产整合的验收：** 给出被统一的规则入口、被删除的路径或重复求值、剩余过渡路径及退出条件；相关编辑满足失败原子性和成功一次提交。新增类数量与文件拆分数量作为规模观察，维护收益由依赖和规则减少证明。内存候选与持久 WAL 沿既有契约分别校验。

## M10 集成验收与恢复产品主线

在同一构建汇总各包已完成的连续循环与成本结果，执行原 600 步切格、5,000 步溃坝、完整分层/线性对流、沙床生命周期、正常操作序列、分数抽取盘上往返、操作顺序及固定种子组合。保留原输入、步数、误差和预算要求。

`production-live-budget` 核对完整捕获、重建、求解与提交成本；同时报告节点、片区、累计子步和精度扩展次数。核对生产旧路径已按各包约定清理、失败恢复完整、architecture 与 routing 准确，随后恢复 D01。

## 验证分级与成本控制

| 时点 | 验证与交付 |
|---|---|
| 表示选择 | 独立解析或精确参考、真实失败状态、复杂度和快速计时，得出方案取舍 |
| 每个小增量 | 一次编译复用本次构建，运行相关短契约及受影响的完整循环，报告首次失败与完整步耗时 |
| 生产接入 | 正常流程、最终发布/恢复、代表规模成本及对应旧路径清理共同通过 |
| 包关闭 | 运行相关完整场景与原长期轨迹，保留原输入及断言 |
| M10 | 同一构建汇总并复验跨包流程、生产预算和恢复产品主线的条件 |

精确库存与数值几何按各自契约验收。生产预算从表示选择开始计入决策，精确算术仅在有必要且成本可控的位置使用；独立参考保留完整精度。保持原残差、迭代、累计 4096 子步、整数搜索和存储预算，性能问题通过算法与重复工作处理。

测试优先复用既有入口与最小反例。长场景首次失败后保存来源，后续定位复用短重放；相关修复成立后再跑原场景。组装 Gradle 任务前核对实际模式，打包随发布内容或集成需要安排。超时与主动中止单列，测试覆盖和性能计时分别报告。

## 工作包执行规则

每段工作先固定失败机制、输入、完整行为目标、维护收益、依赖、验证范围与投入上限。每 2–4 小时或达到本段上限时，核对已交付结果、剩余风险和下一段估算；投入按连续任务累计。

同一设计连续两次被独立反例否定，或已显示规模成本不可接受时，结束该候选的生产扩展，先比较自由度、守恒、可表示性和成本。方案比较交付后再选择下一路线；基础表示待定期间，限定相邻模块的接入与专项优化。研究参考和生产替换分别记录完成状态。

进度记录只保留当前通过范围、未完成行为、复现入口和下一交付。预计投入在依赖成立后分段给出；后续实现量暂不确定时，明确列出待决问题及解决它的投入上限。普通操作、已声明高压高温和持久化要求继续覆盖，功能扩展依产品路线安排。

稳定公式、数据结构与提交契约留在对应 architecture，测试输入和断言留在源码；本计划随交付删去完成项。探索过程和逐轮优化记录由 Git 与会话保存。
