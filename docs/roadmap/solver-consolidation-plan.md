# 当前实施计划：求解器整合

目标是可玩、符合直觉物理、具备工业仿真特色且架构精简的流体 Mod。本文保留当前交付状态与遗留事项。

本页只保留当前工作、未完成项和完成条件，随实际发现调整方向。已实现模型与代码入口见[设计书](../architecture/system-overview.md)，命令、预算和实测见[验证指南](../maintenance/validation.md)，长期功能安排见[产品路线](product-roadmap.md)。历史交付与淘汰方案留在 Git。

## GPU 工作已结束

2026-10-27，按用户要求结束 GPU 化工作。当前交付为实验性 GPU 实现，完整生产后端及性能目标尚未完成。

已实现设备常驻液气机械候选、共同压力、统一整数容量、精确库存输运、有限气体搬运与做功、导热和精确能量账。容量使用活动队列与增量余额，气体组分及允许物种固定寻址，液体汇集直接写入精确体积，连续步复用已提交物理面。生产共同压力使用 GasOperator／Coupled 与结构多重网格。

收尾修复一般残量路径遗留的间接派发，强制排水短重放已通过。连续成本和本次结果见[验证指南](../maintenance/validation.md)。当前实验结果表明仍有明显的成本和生产集成问题，技术可行性尚无定论。

工作区保留未接入生产链的三个相变草稿：`VulkanLiquidPhaseRows.java`、`liquid-phase-rows.comp`、`liquid-phase-rows.glsl`，保持未提交状态。后续任务由用户另行指定。

## 验证与工作量控制

先让耗时达标，再做集中物理验证。性能开发期间只保留识别失效所需的库存、容量、有限数值和实际活动量观测；有95%把握的内容不重复验证。未知风险优先复用既有失败短重放，修复后回到原连续场景。

原64³切格与32³颗粒容量输入继续保留。正式场景、命令、误差和预算统一在[验证指南](../maintenance/validation.md)维护，生产GPU完成要求见[后端参考](performance-and-backends.md#生产-gpu-的完成要求)。集中验收覆盖守恒、真实容量、宏观流动、热化学及故障恢复；视觉、复杂VoxelShape和跨重启交接才安排必要人工观察。
