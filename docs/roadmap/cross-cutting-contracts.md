# 跨层协议、渲染与功能门契约

本文保存所有未来里程碑共同遵守的边界。当前已经生效的纯水规则见 [流体求解器契约](../architecture/fluid-solver.md) 和 [`region-state v1`](../architecture/region-state-v1.md)；这里的新增字段仍需各里程碑单独冻结。

## 状态分层

每项改动必须先归入物理真值、数值离散、渲染重建、调度策略、世界事务或协议/存档，不能用下游层掩盖上游错误。

### 物理真值

- marker `particleVolume` 是液体体积真值；组分库存是化学物质量真值。
- species 的每 AU 质量、组成向量和电荷必须闭合。
- 动量属于运动流体/颗粒；M9 加入后，内能而不是显示温度成为热量真值。
- 密闭气体节点保存体积、组分库存与压力状态；稳定沉积保存材料 ID、数量、孔隙率和必要组成。
- 指示剂只是随 parcel 移动的二值显示标记，没有质量、浓度或反应计量，也不能影响密度。

### 数值离散

- MAC 速度、压力、平滑 `volume[]`、PLIC/cut-cell 分数和曲率都只是离散状态。
- marker 占据继续决定压力相区；多密度压力升级为 `div((1/rho) grad(p))`，不是每种材料各求一套压力。
- 可互溶物共享速度/压力并输运组分；不可互溶物共享机械压力但保留相标签和界面。
- 流体-空气、流体-固体和液液界面使用一致的分数面积/体积；先验证压力边界，再接入表面张力。
- 碰撞仍只限制墙面法向。颗粒可使用更小碰撞半径，但不能仅为颗粒把整个压力网格每轴翻倍。

## 客户端渲染

- 客户端只消费服务端只读快照，不能修改体积、组分、压力、反应或温度状态。
- marker mask 在多材料后扩展为材质/相 palette，仍是稀薄流体的内部种子。
- 混合液颜色从组分连续派生；不可互溶界面不能因 density 卷积被误画成化学混合。
- M3 外表面从总液相占据场重建；内部液液界面从分相字段使用 multi-material/partitioned marching tetrahedra 重建。
- 一块共享液液界面只生成一次，必须有稳定归属、正确法向且无重合双层表面。
- 指示剂颜色从当地近似 pH 与可见标记比例派生，不成为化学浓度。
- 开发命令域默认显示 debug，正式控制器域默认关闭但可手动打开。
- 表面张力负责物理聚集，marker mask 负责浅水可见；两者不可互相替代。

## 网络协议

- `protocolVersion` 独立于 takeover journal 和 region-state 格式版本。
- 登录/配置阶段协商版本与 capability；无法协商时给出可读拒绝，不能尝试错位解码。
- 快照至少带维度、区域 UUID、状态 generation、单调 sequence、material palette 版本和长度明确的可选段。
- M3 多材质、M5 气压和 M7 指示剂必须通过新协议版本或已协商 capability 扩展。
- 客户端只接受当前区域 generation 的递增序列；区域重建、后端切换、移除 tombstone 或重连都不能让迟到旧包复活状态。
- 协议兼容矩阵、未知可选段跳过和 codec 往返是发布门，不能只靠两端同时修改 record 后手工进服。

## 存档与世界事务

- 世界方块修改前必须先存在可恢复 journal。
- 流体状态成功发布与原版方块移除必须有明确共同事务边界。
- 未解决、未知或不可读 journal/state 必须锁住相应新操作，不能覆盖恢复数据。
- 每种格式独立版本；新版本必须保留旧 reader、显式迁移和原子发布，不能直接序列化整个 Java 域对象。
- GPU 缓冲和客户端 payload 都不能成为存档格式。

## Feature flag 与发布回退

- 每个未完成里程碑使用独立服务器配置门；自动门和迁移门完成前，gameplay 入口默认关闭，开发命令只允许管理员显式调用。
- 方块/item 可以随 Mod 注册，但功能关闭时必须拒绝新激活、不得创建新世界状态，并保留已有状态的只读恢复或导出路径。
- takeover 范围、控制器上限、GPU 后端、气体、化学和颗粒分别门控，不能只用一个总开关。
- 关闭或降级功能不得删除已有物质，只能暂停、原子落盘、恢复原版状态，或要求管理员执行有说明的迁移。
