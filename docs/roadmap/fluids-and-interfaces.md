# 多液体、界面与实体耦合规格

本文保存 M3、M4 以及后续双向实体耦合的数值路线。当前已生效的 PLIC、cut-cell、marker 真值和碰撞规则见 [流体求解器契约](../architecture/fluid-solver.md)。

## M3 可变密度压力

升级顺序必须保持小而可退化：

1. marker 增加最小材料/相标签与物理质量，`particleVolume` 继续独立保存；
2. P2G 同时重建面动量、体积与质量；
3. 同密度两材料在独立 3D 连通器中严格退化为当前纯水解；
4. MAC 压力矩阵使用变系数压力算子，G2P 第一版仍输出共享混合物速度场；
5. 覆盖 1:1、1.25:1 和至少 13.6:1 密度比的静水误差、界面寄生流、PCG 迭代和残差；
6. 通过同液 U 形管等高、不同截面连通器、不同密度液柱压强平衡和翻转后稳定分层。

M1 的独立 CPU 系数门已选择按界面距离加权的守恒 `1/rho` 面系数作为 M3 候选；它在一维有限体积柱中保持矩阵对称正定并优于两个平均方案。该结果只选择候选离散，不能替代 3D 接入门。

独立 3D 连通器与活动 `FlipFluidDomain` 竖管门都已覆盖同密度严格退化、1.25:1 与 13.6:1；自由面和液液界面距离分别进入矩阵、预条件器与投影共享的面系数。活动核心还通过了不同截面连通器液位收敛与重轻液翻转分层，并逐材料保持精确质量；正式世界入口仍未创建多材料状态。

不得以不同重力、强制排序 marker、每 tick 调平、墙角偏置或渲染噪声伪造密度效应。

## M4 表面张力与润湿

- 液气和液液表面张力由材料定义。
- 界面曲率产生压力跳跃或等价体积力，并用 balanced-force 离散限制寄生流。
- 固体润湿只由材料接触角定义，不写死“水喜欢墙”或浅水吸引。
- 合并与断开继续守恒 marker 精确体积。

最低验证包括零重力静滴压力跳跃与半径关系、静滴无持续寄生流、液滴合并/断开体积守恒，以及同体积液体在不同接触角表面的铺展差异。不得用渲染收缩替代表面张力。

## 液液界面与渲染边界

- 不可互溶相共享机械压力；第一版共享速度场的限制必须对外明确。
- 外表面与内部液液界面分别重建，不能重合或互相吞掉。
- 内部界面采用 multi-material/partitioned marching tetrahedra；共享界面只生成一次，并具有稳定归属与法向。
- 客户端 palette、颜色、界面 mesh 和平滑字段都是展示数据，不结算材料质量或体积。
- protocol 与 `region-state` 的材料字段只有在兼容和迁移方案评审后才冻结；M3 初期实验保持 CPU 独立状态。
- M3 的基本输入/输出先覆盖纯材料和简单混合物；完整原版桶矩阵留到 M6.1。

CPU 参考 mesher 已实现 pairwise partitioned tetrahedra：每个 pair 的 `f_a = f_b` 平面再由其他 phase dominance 与总液相边界裁剪。自动门覆盖互溶材料不生成内部面、二相平面单一归属、三相交汇三组 pair，以及外表面/内部面无重复三角形；该几何尚未接入客户端绘制。

## 实体耦合的长期目标

当前按浸没比例的单向浮力只是已生效原型，未来目标为：

- 在实体碰撞表面积分流体压力，自然产生浮力；
- 黏性和形状阻力独立计算；
- 实体表面速度作为移动固体边界进入投影；
- 压力与阻力反作用量传回流体，实现双向动量守恒；
- 实体占据体积挤开等量流体，容量不足时显式失败而非删除水量。

Minecraft 首版可使用离散表面采样，不要求一次实现完整刚体联合求解器。
