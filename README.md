# Matter, Motion & Mechanics

Minecraft Java 26.2 / Fabric 流体模组。玩家用外壳方块和控制器围出封闭空间，模拟其中的液体、气体、颗粒、化学反应、传热与相变。当前最多支持四个独立区域，物理计算使用 CPU 单元有限体积液体输运与持久 MAC 动量。

## 在游戏里使用

1. 用玻璃和铁锭制作 `fluid_boundary`，用比较器、红石和铁锭制作 `fluid_controller`。创造模式也可从模组物品栏取得它们和快速入门手册。
2. 用外壳方块和一个控制器围出唯一的封闭内腔，并保持所在区块加载。
3. 空手右击控制器，创建区域并开始运行。再次右击选择区域，空手潜行右击切换暂停状态。玩家选择的运行状态会写入存档。
4. 创造模式可用氮气、氧气、二氧化碳、水蒸气或空气源，对准气体空间的外壳右击注入，潜行右击抽取。每次最多操作 1 m³ 标准体积（101325 Pa、293.15 K）。
5. 创造模式取得有限换热器，对已启用区域的流体围墙右击安装。换热器固定朝北／南交换热量，两侧可接同一区域中的液体、气体或固体载体。空手右击查看温度、质量和内能，空手潜行右击拆卸；物品保留设备质量与内能，原位置恢复围墙。
6. 手持物质场探针右击控制器，查看状态和操作界面。管理员可依次预览并确认清空凝聚相、排气、释放世界方块归属、移除空区域。

控制器可向比较器输出液位信号：空腔为0，部分装液为1–14，液体占满固定可用内腔时为15。容量按固定方块碰撞计算，实体和颗粒运动保持同一标尺；主动暂停保留液位信号，区域不可用、卸载或移除时归零。实体接触区域中的水还会清除原版燃烧标志，这项湿接触响应保持区域物质与内能。

让区域水相实际接触耕地即可补水，每提供足额1 L水，原版湿度增加一档（0–7，满湿共7 L）。水携带的质量、溶质与内能转入土壤汇；油不补水。雨水、原版水块和原版失湿继续采用各自的环境来源与散失规则。主动暂停区域时停止补水。

外壳破损或所需区块卸载时，区域暂停计算，保留玩家原先的运行意图。固定碰撞在每个求解单元内支持一个连通开放空间，隔墙需由求解网格解析。当前游玩范围是控制器内的封闭空间；天然河流、海洋和开放洞穴的接入仍在规划中。

`/mmm` 提供开发场景、诊断和恢复操作。常用命令见 [命令速查](docs/maintenance/commands.md)。

## 构建

目标字节码为 Java 25，现有开发环境使用 JDK 26。在仓库根目录执行：

```powershell
./gradlew.bat assemble --offline --no-daemon
```

`--offline` 使用本机 Gradle 缓存；首次构建缺少依赖时，去掉该参数下载依赖。版本配置在 [gradle.properties](gradle.properties)，模块列表在 [settings.gradle](settings.gradle)。

主模组产物位于 `fabric/build/libs/`，可选 GPU probe 产物位于 `gpu-probe/build/libs/`。部署步骤见 [验收与发布](docs/roadmap/acceptance-and-release.md#release)。

构建缓存、实验输出与本地研究归档的保存位置和清理方式见 [构建输出管理](docs/maintenance/build-outputs.md)。
