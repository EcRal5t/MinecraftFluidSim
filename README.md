# Matter, Motion & Mechanics

Minecraft Java 26.2 / Fabric 流体模组。玩家用外壳方块和控制器围出封闭空间，模拟其中的液体、气体、颗粒、化学反应、传热与相变。当前最多支持四个独立区域，物理计算使用 Vulkan GPU 常驻后端，采用单元有限体积液体输运与持久 MAC 动量。

## 在游戏里使用

1. 用玻璃和铁锭制作 `fluid_boundary`，用比较器、红石和铁锭制作 `fluid_controller`。创造模式也可从模组物品栏取得它们和快速入门手册。
2. 用外壳方块、容器接口和一个控制器围出唯一的封闭内腔，并保持所在区块加载。容器接口由1个围墙、2个铁锭和2个青金石合成，蓝框正面朝外。
3. 空手右击控制器，创建区域并开始运行。再次右击选择区域，空手潜行右击切换暂停状态。玩家选择的运行状态会写入存档。
4. 创造模式可用氮气、氧气、二氧化碳、水蒸气或空气源，对准气体空间的外壳右击注入，潜行右击抽取。每次最多操作 1 m³ 标准体积（101325 Pa、293.15 K）。
5. 创造模式取得有限换热器，对已启用区域的流体围墙右击安装。换热器固定朝北／南交换热量，两侧可接同一区域中的液体、气体或固体载体。空手右击查看温度、质量和内能，空手潜行右击拆卸；物品保留设备质量与内能，原位置恢复围墙。
6. 手持物质场探针右击控制器，查看状态和操作界面；普通玩家可选择、暂停、继续和刷新状态，长摘要可滚轮浏览。管理员先暂停区域，再依次预览并确认清空凝聚相、排气、释放世界方块归属、移除空区域。

手持液体或颗粒容器，对准容器接口的蓝框正面投料或装取；发射器紧贴接口正面并朝向接口，可用红石执行同样的操作。普通围墙保持封闭。创造气体源继续对准实际气腔外壳使用。

控制器可向比较器输出液位信号：空腔为0，部分装液为1–14，液体占满固定可用内腔时为15。容量按固定方块碰撞计算，实体和颗粒运动保持同一标尺；主动暂停保留液位信号，区域不可用、卸载或移除时归零。实体接触区域中的水还会清除原版燃烧标志，这项湿接触响应保持区域物质与内能。

让区域水相实际接触耕地即可补水，每提供足额1 L水，原版湿度增加一档（0–7，满湿共7 L）。水携带的质量、溶质与内能转入土壤汇；油不补水。雨水、原版水块和原版失湿继续采用各自的环境来源与散失规则。主动暂停区域时停止补水。

区域按整体调度和休眠。外壳破损或所需世界区块缺失时区域暂停，保留玩家原先的运行意图和库存；区块重新加载后刷新碰撞并恢复运行。冷恢复分批读取同一代的完整区域存档，库存齐备后准备设备状态。固定碰撞在每个求解单元内支持一个连通开放空间，隔墙需由求解网格解析。天然河流、海洋和开放洞穴的接入仍在规划中。

普通墙采用无滑移，通道阻力由实际湿壁、黏度和流场产生。通道截面建议至少跨四个求解单元，默认约 2 m；窄通道的速度剖面和压降采用粗网格近似。相同压差下，通道变长、截面缩小或液体黏度增大会降低流量。

管理员手持物质场探针，对一池原版静水正常右击预览，10秒内潜行右击确认接管。池底和池壁须为完整实心方块，水面水平、顶部敞开，整个池体需在区域尺寸预算内。每个原版水源记为1 m³水。对接管池的池底或池壁再次使用探针，可预览并确认归还：完整、常温、静止的纯水块回到世界，热水、混合物及零头继续留在暂停的模拟区域，玩家可用容器取走。内容全部交接后解除接管；归还以当前水量为准。

管理员使用 `/mmm demo` 或快速入门手册中的“演示”，打开场景面板。水箱提供水、油水和酸碱配方；水流池可走入观察绕流；气压管提供常压、加压和低压对照。选好场景后开始，或重置到暂停的初态；重复实验保持原位置。水箱有真实控制器和容器接口，可继续用桶投料、装取并观察比较器液位。酸碱配方自动切到 pH 显色，面板也可直接打开显色设置。

`/mmm` 同时提供诊断和恢复操作，原大型溃坝移至 `/mmm damdemo`。常用命令见 [命令速查](docs/maintenance/commands.md)。

## 构建

目标字节码为 Java 25，现有开发环境使用 JDK 26。在仓库根目录执行：

```powershell
./gradlew.bat assemble --offline --no-daemon
```

`--offline` 使用本机 Gradle 缓存；首次构建缺少依赖时，去掉该参数下载依赖。版本配置在 [gradle.properties](gradle.properties)，模块列表在 [settings.gradle](settings.gradle)。

主模组产物位于 `fabric/build/libs/`。部署步骤见 [验收与发布](docs/roadmap/acceptance-and-release.md#release)。

将主模组 JAR（排除 `sources`）与 Fabric API 放入 Minecraft 26.2 / Fabric 的 `mods` 目录即可运行，使用 Java 25 或更新版本。当前发布内嵌 Windows x64 的 GPU 运行库，默认使用 Vulkan 设备0，无需添加启动参数。需要切换显卡时添加 Java 参数 `-Dmmm.gpuDevice=1`。正常请求、观察显示、编辑与存档交接沿生产区域流程推进，启动说明见[运行时说明](docs/architecture/runtime-and-lifecycle.md#startup)，当前实现范围见[实施状态](docs/roadmap/solver-consolidation-plan.md)。

构建缓存、实验输出与本地研究归档的保存位置和清理方式见 [构建输出管理](docs/maintenance/build-outputs.md)。
