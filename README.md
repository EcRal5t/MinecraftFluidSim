# Matter, Motion & Mechanics

Minecraft Java 26.2 / Fabric 流体模组。玩家用探针选择模拟空间，并用原版方块建造容器，模拟其中的液体、气体、颗粒、化学反应、传热与相变。当前最多支持四个独立区域，物理计算使用 Vulkan GPU 常驻后端，采用单元有限体积液体输运与持久 MAC 动量。

## 在游戏里使用

生存模式可从原版材料合成探针、样品容器、物料箱与测量设备，取得相关材料后解锁配方书。合成与操作顺序见[生存模式入门](docs/gameplay/survival-progression.md)。传感器仪表朝外、背面为默认测点；接口青色箭头向内进料、黄铜箭头向外出料，中性标记表示停止。

1. 取得物质场探针与快速入门手册，用铁块、玻璃、石头等方块建造容器，并保持附近区块加载。
2. 手持探针潜行右击两个角点，预览选区、区块与计算预算，再次潜行右击确认创建。选区包含空气、容器壁和设备，原版方块的实际碰撞决定流体空间。
3. 在选区内使用探针打开区域状态，选择、暂停、继续或刷新；`/mmm regionname <名称>` 为当前区域命名。运行意图与名称写入存档。
4. 创造模式可用氮气、氧气、二氧化碳、水蒸气或空气源，对准实际气体空间的壁面注入，潜行右击抽取。每次最多操作 1 m³ 标准体积（101325 Pa、293.15 K）。
5. 在区域相邻空位放置有限换热器，固定朝北／南交换热量。空手右击查看温度、质量和内能，空手潜行右击拆卸；物品保留质量与内能，原位置成为空气。
6. 管理员通过探针界面暂停区域，再依次预览并确认清空凝聚相、排气、释放世界方块归属、移除空区域。

容器接口由1个铁块、2个铁锭和2个青金石合成，蓝框正面朝外。手持液体、颗粒或气体容器，对准接口正面投料或装取；发射器紧贴接口正面并朝向接口，可用红石执行同样的操作。普通方块按实际碰撞阻挡流体。
手持空混合液桶潜行装取，可从接口内侧对应的单个流体格提取局部样品；样品保留实际组成和内能。

手持液体、颗粒或气体容器，潜行对空使用可打开样品分析，查看数量、组成、质量分数、完整物种的摩尔分数、浓度和保存内能对应的温度。保存当前样品为基准后，更换容器再次打开即可并排比较；切换维度或离开服务器清除比较基准。

空手潜行右击工艺传感器可打开历史曲线，横轴为区域实际推进的仿真秒数。曲线读取已有测量结果，暂停与不可用期间断开连线；记录保留在当前会话，测量配置或区域实例改变后重新开始。

液位与温度红石输出由过程传感器提供。实体接触区域中的水会清除原版燃烧标志，这项湿接触响应保持区域物质与内能。

让区域水相实际接触耕地即可补水，每提供足额1 L水，原版湿度增加一档（0–7，满湿共7 L）。水携带的质量、溶质与内能转入土壤汇；油不补水。雨水、原版水块和原版失湿继续采用各自的环境来源与散失规则。主动暂停区域时停止补水。

区域按实际形状分块保存，通道跨计算块连续流动，规模受驻留单元预算约束。液体或颗粒接近计算空间外缘时，区域沿所需方向自动扩展一个计算块，并接管新增范围的碰撞、空气及原版水。预算不足、区块缺失或新范围与其他区域重叠时，区域暂停并显示原因；处理后可在区域面板刷新重试。不同区域共享同一世界坐标的墙体和有限环境空气热库存。所需区块缺失时关联物理组暂停，保留运行意图和库存；重新加载后刷新碰撞并恢复。区域与共享环境通过同一世界存档发布记录恢复。固定碰撞在每个求解单元内支持一个连通开放空间，隔墙需由求解网格解析。

普通墙采用无滑移，通道阻力由实际湿壁、黏度和流场产生。通道截面建议至少跨四个求解单元，默认约 2 m；窄通道的速度剖面和压降采用粗网格近似。相同压差下，通道变长、截面缩小或液体黏度增大会降低流量。

材料属性统一由 `data/mmm/mmm` 下的 JSON 数据定义。液体密度、黏度和显示颜色位于 `fluid_materials`，组分与反应、气体、颗粒及热学由对应目录提供；宿主操作、GPU 仿真与存档使用同一份世界定义。数据入口见[材料状态](docs/architecture/material-state.md)。

原版铁、铜、金、玻璃、木材和石材会蓄热，其余方块使用默认材料。热水先加热容器壁，再与附近四格范围的有限空气交换热量。绝热块 `mmm:insulation` 和绝热玻璃 `mmm:insulating_glass` 的导热系数为零。当前材料支持水–乙醇混合、挥发与冷凝、CO₂ 吸收脱除和碱液反应、盐的析出与溶解；局部组分与温度随流动传播。物料箱和容器接口提供连续进出料，阀门改变真实开口，传感器用红石控制液位和温度。筛截留实体颗粒，普通墙与筛可装填吸附或催化材料。探针打开配置面板，操作步骤见[工艺操作](docs/maintenance/commands.md#工艺操作)。

管理员手持物质场探针，对一池原版静水正常右击预览，10秒内潜行右击确认接管。池底和池壁须为完整实心方块，水面水平、顶部敞开，整个池体需在区域尺寸预算内。每个原版水源记为1 m³水。对接管池的池底或池壁再次使用探针，可预览并确认归还：完整、常温、静止的纯水块回到世界，热水、混合物及零头继续留在暂停的模拟区域，玩家可用容器取走。内容全部交接后解除接管；归还以当前水量为准。

管理员使用 `/mmm demo` 或快速入门手册中的“演示”，打开场景面板。水箱提供水、油水和酸碱配方；水流池可走入观察绕流；气压管提供常压、加压和低压对照。选好场景后开始，或重置到暂停的初态；重复实验保持原位置。水箱使用普通方块、空间选区和容器接口，可继续用桶投料、装取并由传感器观察液位。酸碱配方自动切到 pH 显色，面板也可直接打开显色设置。

`/mmm` 同时提供诊断和恢复操作，原大型溃坝移至 `/mmm damdemo`。常用命令见 [命令速查](docs/maintenance/commands.md)。

## 构建

目标字节码为 Java 25，现有开发环境使用 JDK 26。在仓库根目录执行：

```powershell
./gradlew.bat assemble --offline --no-daemon
```

`--offline` 使用本机 Gradle 缓存；首次构建缺少依赖时，去掉该参数下载依赖。版本配置在 [gradle.properties](gradle.properties)，模块列表在 [settings.gradle](settings.gradle)。

主模组产物位于 `fabric/build/libs/`。部署步骤见 [验收与发布](docs/roadmap/acceptance-and-release.md#release)。

将主模组 JAR（排除 `sources`）与 Fabric API 放入 Minecraft 26.2 / Fabric 的 `mods` 目录即可运行，使用 Java 25 或更新版本。当前发布内嵌 Windows x64 的 GPU 运行库，默认使用 Vulkan 设备0，无需添加启动参数。需要切换显卡时添加 Java 参数 `-Dmmm.gpuDevice=1`。正常请求、观察显示、编辑与存档交接沿生产区域流程推进，启动说明见[运行时说明](docs/architecture/runtime-and-lifecycle.md#startup)，当前实现范围见[实施状态](docs/roadmap/solver-consolidation-plan.md)。

构建缓存、实验输出与本地研究归档的保存位置和清理方式见 [构建输出管理](docs/maintenance/build-outputs.md)。
